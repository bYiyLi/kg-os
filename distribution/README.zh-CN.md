# KG OS

**让 AI 拥有可以查询、修改和回溯的知识图谱。**

[English](README.md) · 简体中文

KG OS 是面向 AI 的可编程知识图基础设施。你可以按自己的工作定义信息与关系，通过 MCP 连接 AI，并保留知识变化的历史。部署在哪里、采用什么知识模型，由你决定；KG OS 与现有 Agent 协作，而不是替换它。

[产品官网](https://kghub.y2l.top/zh/) · [发布版本](https://github.com/bYiyLi/kg-releases/releases) · [问题反馈](https://github.com/bYiyLi/kg-releases/issues)

## 你可以用它做什么

| 你的目标 | KG OS 提供的帮助 |
| --- | --- |
| 按实际工作组织知识 | 自定义对象、关系、属性和约束，不必套用固定的业务模板。 |
| 找到答案及其上下文 | 结合图查询、全文搜索和语义检索，查看信息及其关联。 |
| 理解知识发生了什么变化 | 模型与数据一起保留历史，通过版本比较、分支和合并管理变化。 |
| 让现有 AI 使用知识 | 连接兼容的 MCP 客户端，由官方 Skills 提供建模、知识创建、检索、版本管理、维护、活动记录和诊断规范。 |

例如，把项目中的一项技术决策，与它影响的模块、支持它的证据连接起来。提出修改前，让 AI 先检查这些关系。

## 通过 AI Agent 安装

将下面的提示词复制给能够访问目标安装环境的 AI Agent：

```text
请按照这份官方安装手册帮我安装 KG OS：
https://raw.githubusercontent.com/bYiyLi/kg-releases/main/INSTALL.md

先阅读手册，检查已有环境和实际发布的可用版本，再完成获授权的安装与验证。复用有效连接，保留现有数据。需要我登录或授权时，告诉我具体操作；不要让我把凭证粘贴到对话中。
```

Agent 会根据 [INSTALL.md](INSTALL.md)，按需部署运行时、连接 MCP 客户端，并在客户端支持时安装七个官方 Skill 和知识发现引导词。已有 KG OS 实例可以直接复用，也可以选择只连接 MCP。你不需要再照着另一套命令手动安装。

### 开始前需要准备什么

已有 KG OS 实例，或一台用于新部署的 **Linux amd64 Docker 主机**，以及获准操作该环境的 Agent。Agent 会检查持久存储、向量服务配置和兼容的 MCP 客户端；远程连接还需要可信的 HTTPS 地址或受支持的安全隧道。

使用**发布版本**中实际可用的运行时镜像及对应版本的 Plugin 资源。`main` 分支的文件可能先于正式版本更新。没有合适的可用版本时，Agent 应说明缺少什么，而不是拿占位版本尝试安装。

不要在聊天或公开 Issue 中发送管理员 Token、API Key 等凭证。需要登录或授权时，在 Agent 指明的可信界面中完成。

## 安装后如何开始

可以对 AI 说：“读取我的 KG OS 知识模型和版本概览，说明目前有哪些内容，不要修改数据。”Agent 应验证真实连接，并明确报告哪些部分已可用、哪些不可用、哪些仍需要你操作。

初始化和连接授权使用**你部署的实例地址**。产品官网只介绍 KG OS，不是你的知识工作区。[官方 Skills](plugins/kgos/skills/)帮助 AI 使用知识；遇到问题时，可以按需运行 `kgos-doctor` 做只读检查。

## 遇到问题

先让 Agent 在不修改数据的前提下诊断。仍无法解决时，通过 [Issue](https://github.com/bYiyLi/kg-releases/issues) 提供 KG OS 版本、客户端、主机平台、失败步骤和脱敏后的错误信息。不要附带凭证、私人连接配置或知识库数据。
