## 11:50 — SemanticText 参数与托管向量结果边界

### Decisions

- 删除上一版公开 `Graph embed` / `kg graph embed`。KG OS 不为语义检索解析、验证或改写 Cypher；Lithograph 继续是唯一 Cypher parser/planner/executor。
- Graph params 新增唯一 KG OS-only 输入 marker：top-level parameter value `{"$semantic":"text"}`。KG OS 仅根据 marker 调用全局 Embedding Provider，将其替换为标准 Lithograph Vector parameter，再把原始 Cypher 交给 Lithograph。
- managed semantic vector 是内部 materialization：不能出现在 Object Value、Node/Relationship public properties、`properties()`、`keys()`、projection/dynamic property access、History/Diff 或调用方可写 slot。Vector `SEARCH` 正常返回调用方指定的业务数据与 score，不附加 embedding。

- Full-text 保持原模型；hybrid query 使用两个参数：普通 String 给 Full-text，SemanticText 给 Vector SEARCH，避免 KG OS 猜测参数用途。

## 13:05 — 移除 caller-owned Vector 并深度复查语义检索设计

Scope and authorization: 用户进一步明确 KG OS 不需要公开 `VECTOR<FLOAT32>(...)` 业务 Property，并要求重新整理、优化设计文档并深度 review。本轮继续只修改 KG OS 设计/日志；Lithograph 只读核对，不实现代码、不提交、不推送。

### Decisions

- 新增 D49：KG OS v1 public Ontology / Knowledge / Graph value profile 不公开 caller-owned Vector。Property `type` / type constraint 不接受 `VECTOR<...>`，Object/Knowledge 不保存 Vector，Graph 不接受 raw Vector parameter、也不返回 Vector result；`type: vector` 只保留为托管 semantic Index 的 Index type。Lithograph 自身仍是通用数据库并完整保留 Vector 能力。
- 11:50 条目中“普通业务 `VECTOR<...>` Property 仍可公开”的设计已被 D49 **明确取代**；历史日志保留原记录，不回写伪造当时状态。
- Lithograph Graph Type 是 open semantics，因此仅在 Ontology 禁止 Vector 不足以关闭旁路。Graph mutation 必须在 durable commit 前检查实际 candidate/staged changes，拒绝 caller-owned Vector 与 caller 写入 `__kgos_` reserved identifier；绕过 KG OS 产生此类数据的 Snapshot 属于 KG OS-invalid State。
- `graph execute` 仍是 raw Cypher command，不新增 KG OS parser/rewrite，也不要求 caller 提供 `baseState`；成功时 caller mutation、public-profile validation 与 mandatory managed semantic migration 必须共同形成一个最终 State，并保持 Lithograph mutating-query 的 write-intent/empty-delta Commit 语义。
- semantic Index create/delete/targets/source 变化必须在同一个最终 State 对已有 Knowledge backfill/recompute/remove managed materialization；Node Label / element create-delete 导致 target membership 变化时同样处理，不能只监听 source Property value。
- SemanticText 只在 Graph `params` 的直接 value 位置识别；其它 Map/Object/State Data 中 `$semantic` 没有特殊含义。raw Vector 只要不跨越 caller param/result/durable data 边界，Cypher expression 内部的 Lithograph Vector 计算不由 KG OS 解析拦截，也不成为 KG OS public Vector API。
- embedding-space fingerprint 改为覆盖全部 vector-space/search semantic non-secret config：provider/model/dimension/similarity、KG OS framing version 与存在时规范化 `base_url`；credential 不参与，所以 key rotation 不要求 migration。相同配置身份下远端 provider 静默替换同维度向量空间仍是外部 provider stability 限制。

### Deep review findings and fixes

1. **Open Graph Type bypass**：确认 Lithograph `docs/design.md` §11.1 保留 open Graph Type semantics；补齐 Graph staged/candidate validation 与 D31 invalid-State 边界。
2. **Writer-lock / network conflict**：确认 Lithograph §9.2 从 `tx_begin` 起持有 single-writer，并明确要求 transaction 不等待长时间网络 I/O。删除“`tx_execute → Embedding Provider → tx_commit`”这种看似原子但违反底层约束的实现假设；动态 semantic-source/target mutation 新增 candidate/preparation readiness blocker。Object/Ontology Patch 因 baseState + target delta 已知，可在 writer lock 前预计算 embedding，再用 expectedHead 原子落地。
3. **Version semantics contradiction**：修正 Evolution 原来“Graph execute 不继承 one-State guarantee”的旧表述；它不继承的是 Object Patch 的 caller-supplied strict `baseState`，但成功的 caller mutation + mandatory derived changes 仍必须只有一个最终 State。
4. **Target membership omission**：补齐 Label、element create/delete 等导致 semantic Index target membership 变化的 managed-vector create/delete。
5. **Streaming failure boundary**：修正 CLI “失败 stdout 必为空”与 Graph streaming partial rows 的旧冲突；stream 已开始后错误允许 partial NDJSON，但无 final summary 即整体失败。`execute --stream` 的 elementId 在 final summary 前都是 provisional。
6. **SemanticText key pollution**：修正 `$semantic` 在非 Graph-direct-param surface 的误保留；只在明确识别位置有特殊意义。
7. **Fingerprint endpoint omission**：补齐自定义 provider endpoint 对向量空间身份的影响；secret/credential 明确排除。

Source state and environment: KG OS worktree 基于已推送的 `dc87cac`，叠加本轮及上一轮尚未提交的设计变更；Lithograph 仅只读核对当前 `docs/design.md`、Graph View 与 transaction / search 公开合同，没有修改其工作区。

## 15:50 — v1 OpenAI-compatible Embeddings 配置合同

Scope and authorization: 用户确认 v1 先只支持 `openai-compatible`，要求写入设计，并明确 `api_key_env` 与直接 `api_key` 都要支持。本轮继续只修改 KG OS 设计/日志，不实现代码、不修改 Lithograph、不提交、不推送。

### Decisions

- 新增 D50：v1 不提供 `provider` 配置、provider registry 或 plugin system；唯一远端 embedding protocol 是 OpenAI-compatible Embeddings 子集。
- `[embedding]` 必填 `base_url / model / dimensions`，`similarity` 缺省 `cosine`。`base_url` 是 API root，KG OS 请求 `${base_url}/embeddings`；`dimensions` 用于本地 Vector Schema/Index 与响应长度校验，v1 不发送远端 `dimensions` request parameter。
- `api_key` 与 `api_key_env` 都支持、互斥；两者都不配表示无认证。任一方式得到 credential 后发送 `Authorization: Bearer <credential>`。inline `api_key` 是明确支持的便利配置，`api_key_env` 是减少 secret 落盘的推荐方式。
- secret 不进入 State、Commit Data、fingerprint、日志或错误输出。credential source/value 改变需要 restart 重新读取，但不要求 embedding migration。
- OpenAI-compatible wire 只冻结 Embeddings 子集：JSON request 使用 `model + input`，input 可以是 String / Array<String>；response correctness 只依赖 `data[].index + data[].embedding`。缺失/重复 index、非 finite 数值、维度不符、非成功 HTTP、JSON/shape/transport failure 均为 `EMBEDDING_PROVIDER_ERROR`。
- embedding-space fingerprint 使用固定 protocol identity `openai-compatible-embeddings-v1` + canonical base_url/model/dimensions/similarity/input-framing；credential source/value 不参与。

### Evidence / review

2026-09-16 核对 OpenAI 当前官方 Create embeddings API reference：endpoint 为 `POST /embeddings`，request 支持 `model` 与 String / Array input，response `data[]` entry 提供 `embedding` 与 `index`；官方 API 使用 Bearer API key。KG OS 只冻结自己实际需要的这个子集，不把 OpenAI 其它 API 或可选 request fields 提升为兼容要求。
