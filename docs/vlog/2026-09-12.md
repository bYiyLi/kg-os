## 16:55 — Evolution Merge Session design synchronization

Scope and authorization: 用户要求把大量 merge conflict 可分页、可逐步解决的方案同步到 KG OS 设计，并与 Lithograph 新的 Merge Session 公共合同对齐；本任务只修改 README/设计文档与开发日志，不实现业务代码、不提交、不推送。

### Decisions

- Evolution Merge 从一次性调用改为 `merge.start/list/get/conflicts/resolve/finalize/abort` 多步 lifecycle；Session token 只是未完成 merge 的 operational identity，不是 StateRef/ObjectRef，KG OS 不建立自己的 merge workspace 或 conflict persistence。
- `merge.conflicts` bounded/pageable；AI/用户可以分批提交 resolution，任意中间步骤都不产生 KG OS State、不移动 Branch。
- KG OS 直接复用 Lithograph opaque `conflictId`，只把底层 slot/base/ours/theirs 投影成公开 Object/Knowledge `kind/path/value`；resolution 的 explicit value 再确定性映射回对应底层 slot，不维护第二套 conflict identity。
- `merge.start` 后以 Lithograph 实际 pin 的 `targetState/sourceState` 做 D31 consistency check；任一无效就立即 abort Session，避免 Branch/Tag 预检查与底层 pin 之间的 check-then-use race。
- unresolved=0 后，KG OS 在固定 `(session, revision)` candidate 上检查 Binding coverage、reserved internal Schema/graph 等 KG OS-valid invariants；通过后用同一 revision finalize。Lithograph 的 revision CAS + target-head CAS 保证被 KG OS 校验的 candidate 不会在提交前静默变化。
- candidate validation 失败保留 Session，不提交 State；调用方可以调整已有 conflict resolution 后重新验证，或 abort 并先通过正常 Object/Graph mutation 修复 source/target。v1 不增加“直接编辑 merge candidate”的第二 mutation surface。

### Corrections

- `merge.start` 不再“先创建底层 Session 再检查 pinned State”。KG OS 先把 target Branch head 与 source 解析成 immutable State 并完成 D31 consistency check，再调用 Lithograph `merge.start(source=sourceState, expectedHead=targetState)`；Branch 在检查后移动时底层原子返回 `BRANCH_HEAD_MOVED` 且不创建 Session，因此无效 State 不会先暴露成公开 workspace。
- `merge.abort` 增加 `expectedRevision`；resolve/finalize/abort 三类 Session mutation 都使用 revision CAS，stale caller 不能删除或覆盖更新后的冲突解决进度。
- KG OS 继续直接复用 Lithograph opaque `conflictId`，只负责 public Object/Knowledge slot/value projection；不建立第二套 conflict identity/workspace。
- Candidate consistency validation 仍绑定 exact `(session, revision)`；Lithograph finalize 的 read-preparation + short-writer revision/head CAS 保证 KG OS 检查的 candidate 与最终提交 candidate 不漂移，同时避免大型 merge validation 长时间持有 writer。

Final cross-layer review additionally covered Sessions created by a maintenance tool that bypasses KG OS.
