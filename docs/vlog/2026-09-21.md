## 23:08 — KG OS 服务端切换 Go，并对齐 Lithograph v0.3.0

Scope and authorization: 用户确认 KG OS 采用 Go，并要求整理新方案、维护设计文档和开发计划。本轮只修改 KG OS 文档与计划，不迁移代码、不删除当前未提交 Phase 01 实现、不提交、不推送。

### 已确认的新工程基线

- `kgosd`、Kernel、SQLite / Lithograph adapter、projection/compiler、consistency validation 与 `kg` CLI 改为 Go；SDK 与浏览器 Web 继续使用 TypeScript。
- Web 仍随同一个 `kgosd` 交付，由同一 configured host/port 提供页面、静态资源与 API/control；开发阶段可以使用 Vite dev server + proxy/HMR，但不形成第二个产品部署服务。
- 服务端 HTTP 使用 Go `net/http`；SQLite host 目标使用 `database/sql` + `github.com/mattn/go-sqlite3`。长查询、streaming、request disconnect 与 daemon shutdown 通过 `context.Context` 对接 driver / SQLite interrupt，不采用 Node DB worker/child-process IPC 或 application Native query ABI。
- 当前 Go 工具链目标固定为 Go 1.27.1；本机现状仍是 Go 1.25.4 + Apple Clang 21，因此本轮没有把新工程基线误报为已实现。

### Lithograph v0.3.0 接入调整

- KG OS application-facing database integration 改为 SQL-only：完整结果使用 `lithograph()`，streaming 使用 `lithograph_rows()`，validation 使用 `lithograph_validate()`。
- 多 execution 单 Commit 使用 `lithograph_tx_begin() -> lithograph()/lithograph_rows()* -> lithograph_tx_commit()/abort()`；删除旧设计中的 `lithograph_tx_execute()`、Native query ABI、`sqlite3*` ownership 与 same-handle adapter要求。
- Graph `query` / `execute` 继续只决定 read-only / read-write connection，不解析 Cypher。Semantic、`LOAD CSV`、write、Schema/Version procedure 与 transaction subquery都继续由 Lithograph判断；streaming统一使用 `lithograph_rows()`。
- Lithograph Core 不再拥有 persistent text→Vector cache。OpenAI-compatible Provider 的 `providerConfig.cache` 只接受 `enabled/path/max_bytes`；enabled时必须显式 path，Provider自己维护与 Lithograph main隔离的 SQLite cache。
- KG OS 保留 `[cache]` 作为 OpenAI-compatible Provider 的默认配置：省略 path时使用 `$KG_HOME/cache/openai-compatible.db`；relative path相对 effective `KG_HOME`解析，写入 versioned providerConfig 前转换为 absolute path；KG OS只创建父目录，不创建/ATTACH/读写 Provider cache DB内部结构。
