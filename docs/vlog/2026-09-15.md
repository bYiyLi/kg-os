## 08:25 — Ontology scoped patch 与 batch read

范围与授权：用户确认采用 `kg ontology patch` 作为职责更明确的 Ontology 写入口，并明确要求 Ontology 读取支持批量读取。继续只修改设计文档，不实现代码、不提交、不推送。

### 决定与修改

- `kg ontology` 支持一次读取 1..100 个 typed Ref；整个 batch 只解析一次 `at` 并固定到同一个 immutable State，外层保持请求顺序，任一目标失败则整批失败。
- batch 中每个 Domain 可以返回自己的 cursor；cursor continuation 用该 Domain 单 Ref + batch 返回的 resolved State 单独继续。`--edit` 保持单 Ref，避免引入 multi-document editable bundle。
- 新增 `kg ontology patch`；它复用 Object Patch 的文本格式、strict base、alias、并发、错误、transaction 和 result，只允许 Domain / Node Definition / Relationship Definition target。跨 Ontology + Knowledge 的原子修改继续使用 `kg object patch`。
- 同步 ontology、cli、object、implementation、README、设计索引和 D43，并新增 D47 记录本次确认。

### 验证与剩余

已重新检查全仓 Markdown：106 个 fenced block 闭合、91 个相对链接/标题锚点有效、9 个 JSON 示例仍可解析；新增 batch/scoped-patch 语义检查 13/13 通过，确认 logical `refs[]`、1..100 上限、同 State、all-or-nothing、单 Domain cursor continuation、单 Ref `--edit`、CLI variadic refs、scoped patch、Knowledge target 拒绝、D47 与 implementation acceptance 均存在且相互一致。`git diff --check` 通过，并扫描确认没有残留“不能有 kg ontology patch”“Ontology 修改全部只能 kg object patch”或 D1–D46 旧索引表述。

当前仍只有设计，无 Ontology reader / patch runtime 实现；上述检查只证明文档和示例合同一致，不证明运行时已实现。未提交、未推送。

## 08:40 — Batch edit 使用 YAML multi-document stream

范围与授权：用户进一步确认批量 `--edit` 应与批量 Patch 对齐，并接受标准 YAML multi-document stream 方案；同时要求整理进设计后整体 review。继续只修改设计/使用文档，不实现代码、不提交、不推送。

### 决定与修改

- `kg ontology ... --edit` 从单 Ref 放宽为 1..100 Ref；所有对象固定到同一个 immutable State，任一目标失败时 stdout 为空。
- 单 Ref输出保持纯 canonical YAML；多 Ref输出使用标准 YAML 1.2 multi-document stream。`# kgos-state` 与 `--- # kgos-ref` 仅是 CLI framing comment，每个 document body 与单 Ref canonical YAML 逐字一致。
- 不采用 output directory、自动拆 YAML 文件或 `{ref, value}` wrapper；这些会引入文件身份或改变 Git Patch base。
- 同步 Ontology、Object serialization、CLI、D43/D47、implementation acceptance 与 README；multi-object Patch 仍使用同一个 `kg ontology patch` / Object Patch engine。

### Review

本轮按 Ontology / Object serialization / CLI reference / shared errors / Decision / implementation acceptance 做了整体一致性 review。第一轮发现并修正 3 个实际 finding：batch YAML 示例里的 Document/AUTHORED 曾是缩略体，与“document body 必须逐字等于单 Ref canonical YAML”冲突；共享错误合同未明确 batch `--edit` 与 ontology-patch scope 的失败分类；CLI required-text-input 表只写 Object Patch，没有明确同样覆盖 Ontology Patch。

修正后验证：全仓 109 个 fenced block 闭合，92 个本地链接/标题锚点有效，9 个 JSON value 可解析，8 个 YAML block/stream 可由现有 Ruby/Psych 解析且无重复 mapping key；batch edit stream 恰好有 3 个 document，Person/Document/AUTHORED 三个 raw body 与各自单 Ref canonical 示例 3/3 逐字一致；9 项 batch/edit/scoped-patch 语义检查全部通过；`git diff --check` 通过。旧 `Property/Constraint/Index Object` 和 `graph-type:/property:/constraint:/index:` 字样只剩否定当前能力或 Decision 备选说明，没有作为现行接口残留。

本轮未发现当前设计真源中其它会使 batch read/edit、canonical YAML、Ontology Patch/Object Patch、Graph/Evolution 边界产生不同实现答案的 finding。未验证项仍是运行时实现本身：当前仓库没有 Ontology reader/compiler/CLI 代码，因此上述结果是设计与文档一致性验证，不是运行测试。未提交、未推送。
