Implementation:

- CLI root 统一为 `--root <workspace-root> > KGOS_ROOT > error`，所有 Instance 状态固定派生到 `<root>/.kgos`；Go `kgosd --root` 同样接收 Workspace Root。legacy v0.1.x root-is-Instance 组合由 `init/doctor` 明确诊断，不做自动迁移或双读。
- init 配置字段收敛到 shared schema，驱动 config validation、flags、wizard 与 help；new Instance 默认 `jieba`，non-interactive additional extensions 使用互斥的 `--extensions-file` / `--no-additional-extensions`。
- `init` 从 config writer 改为 complete setup：配置发布后复用真实 daemon startup path完成 official/additional extension materialization、credential、`kgos.db`、Lithograph/KG OS bootstrap、active locator与 authenticated readiness。成功后原子写 `.kgos/initialized.json` completion receipt；业务 Runtime ensure 在 receipt 缺失时拒绝隐式首次 bootstrap，再次 `init` 负责 resume。
- doctor 对齐 Workspace/Instance、legacy、config、Runtime package、extension materialization/source、environment、credential、database、completion receipt 与 daemon状态；Unix CLI读取 `auth.json` 时与daemon一致要求 `0600`。
- help 改为 root / namespace / leaf 渐进披露；root说明 `--root > KGOS_ROOT`，leaf包含必要范围、互斥与主路径示例。Web开发壳与开发脚本同步使用 Workspace Root / `.kgos` 语义。
- review发现 graceful stop 后旧 locator 会让已初始化 Instance 被 doctor误判 unavailable。未在 TypeScript CLI引入第二套file-lock协议；改为权威 `InstanceLock.Close()` 在正常退出时先清空并sync locator再释放OS lock。SIGKILL/crash仍保留stale locator，继续按D79由daemon contender获取真实OS lock完成恢复。
