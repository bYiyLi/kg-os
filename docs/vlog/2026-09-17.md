## 14:44 — 冻结 KG_HOME 单库与单 Token 认证

Scope and authorization: 用户明确决定 `kgosd` 每个 profile 只打开一个 Knowledge Base，默认 home 为 `~/.kgosd`、允许通过 `KG_HOME` 指定；随后要求增加 `auth.json` token 认证，并确认 CLI 通过 `KG_TOKEN` 环境变量提供 credential，最终要求整理并写入设计文档。本次只同步 KG OS 设计/日志，不实现代码、不修改 Lithograph、不提交、不推送。

### Decisions

- 新增 D54：`KG_HOME` 是完整 runtime profile selector；未设置时默认 `~/.kgosd`。一个 profile 最多一个 active `kgosd`，固定只承载 `$KG_HOME/data/kgos.db`，不建立 Knowledge Base registry、`--base` 或单 daemon 多库切换。
- 新增 D55：每个 profile 使用 `$KG_HOME/auth.json` 保存一个持久 server token。首次 daemon startup 缺文件时安全随机生成并原子写入，restart 复用；malformed/unreadable credential fail closed，不自动 rotate。
- 所有 daemon data/control HTTP request 使用 `Authorization: Bearer <token>`。CLI 只从 `KG_TOKEN` 读取 client credential，不读取 `auth.json`、不提供 `--token`；SDK/Web 同样不能获得 credential-free API 旁路。
- 当前 profile 没有 active daemon 时，`kg daemon start` 允许先执行本地 process spawn；它通过 child 成功取得 lock 并在完整 startup validation + HTTP bind 后发布 endpoint 判断 ready，不读取 `auth.json`、不调用未认证 health API。active daemon 已存在后，`start/status/stop/restart` control HTTP 与其它请求一样必须认证。
- 认证只证明持有实例 secret，不引入 user、role、scope、OAuth、refresh token 或多租户授权。v1 仍不内置 TLS；non-loopback plaintext HTTP 的 bearer confidentiality 由 operator 自行承担。
- `AUTHENTICATION_FAILED` 成为统一认证失败 code；missing/malformed/wrong token 对外不区分。CLI 缺/空 `KG_TOKEN` 在 dispatch 前以该 code + exit 2 失败，daemon 401 则 exit 1。

## 15:05 — Embedding cache 与 KG_HOME 根目录布局

Scope and authorization: 用户要求向量处理增加专用 cache，确认使用 `cache.db`，要求在 `config.toml` 提供 cache 配置，并最终确认默认开启、默认最大 4 GiB、超过后清理旧数据；随后明确删除 `data/` 中间层，让 Knowledge Base 直接使用 `$KG_HOME/kgos.db`，并要求整理写入设计文档。本次继续只同步 KG OS 设计与日志，不实现代码、不修改 Lithograph、不提交、不推送。

### Decisions

- D54 当前布局修正为 `$KG_HOME/kgos.db`，不再保留 `$KG_HOME/data/`；`cache.db` 与 `kgos.db` 同级，但前者是 derived runtime cache，后者是唯一 Knowledge Base 真源。
- 新增 D56：`$KG_HOME/cache.db` 是标准 SQLite Embedding result cache；`[cache]` 默认 `enabled=true`、`max_size_mb=4096`，配置 4096 按 4 GiB 解释。
- 超过容量上限时按 least-recently-used 顺序淘汰最久未使用 entry，并要求回收 SQLite free pages；不通过 TTL 或其它 eviction strategy 增加配置复杂度。
- cache identity 包含 embedding protocol/cache format、canonical base_url、model、dimensions、input framing 与 exact provider input；credential 与 similarity 不参与。cache 不保存原始业务文本，不缓存失败响应。
- `cache.db` 不是 correctness source：不存在、损坏、格式不兼容或 I/O 失败都可以退化为 miss/bypass 后重新请求 Provider；删除 cache 不能改变任何权威 State/Commit/Branch 或公共合同，外部 Provider 自身漂移仍遵守既有 runtime stability 边界。

### Changes

同步 Runtime、Architecture、CLI、Implementation、Decisions、设计导航与 README；把当前真源中的 `$KG_HOME/data/kgos.db` 全部迁移为 `$KG_HOME/kgos.db`，并补充 cache config、key、LRU、size reclamation、failure recovery 与实现验收边界。
