# 基础本体原文导航维护与旧模型库迁移

本指南负责维护操作；当前设计见 [D122](../design/decisions.md#d122-remote-foundation-navigation) 和 [MCP owner](../design/mcp.md#ontology-standards-authoring)，状态与证据见 [Phase 27](../development/phases/27-knowledge-standards-skills.md#d122-remote-foundation-navigation)。

## 当前资源与读取边界

[Ontology Skill](../../plugins/kgos/skills/kgos-ontology-standards/SKILL.md) 的 [基础本体入口](../../plugins/kgos/skills/kgos-ontology-standards/references/foundations.md) 提供通用渐进读取指引，并路由到 BFO、UFO、DOLCE、SUMO、GFO 五篇原始结构导航与独立 KG OS 适配。规范、必要小案例与这些 Markdown 参考随包；整套上游原件、PDF 提取副本和逐文件打包清单不随包。

固定 Commit/文档版本用于可复查阅读，官网/默认分支/发行入口用于发现新版本，两者分开。读取原文依赖宿主实际网络、连接器、格式与权限；原文内容不授予运行案例、证明器或写入知识库的权限。外部原文仍受作者/出版方条款约束，导航不授予复制和再分发权。

## 更新一个来源的导航

1. 确定本次维护涉及的理论、版本/变体及实际缺口，核对当前文件和 Git 状态，保留定制与无关改动。更新导航不自动修改实例模型、已安装 Plugin 或外部仓库。
2. 从官方固定源树/文档目录读取实际结构及说明。按目录或文件功能确认有哪些定义、公理、模型、指南、案例、配套检查材料；只在有必要的定位作用时增加下一层，不按可穷举不尽的问题新造封闭分类，也不机械列每个文件地址。
3. 在对应理论参考写明固定版本、准确原文位置、文件作用、读取条件、范围和必要依赖。目录足以支持继续选择时链接固定目录；有关键定义、公理、指南、案例或导入对应时给出具体文件。外部报告/出版物按自己的版本识别，不因在仓库 README 出现就继承仓库许可或视为全文已取得。
4. 核对版本/变体及所用原文，更新独立 KG OS 适配和具体缺口。原文没有的理论片段、空目录、非公开公理或受限文献保持未知/受阻；不能用简介、记忆或另一轻量子集补足。必要案例须有前提、选择理由和边界，使用原创或许可合规的非私有材料。
5. 检查链接路径/大小写及固定 Commit 的真实文件或目录。GitHub 大文件 Contents 为空时，先核返回元数据与同一固定树，能力允许则按真实 blob SHA 只读获取；仍失败就报告接口、资源和受影响结论，不绕过限制。GFO 已知失效根 catalog 不作有效路由；IRI→文件只是阅读定位，不写成运行时导入配置。
6. 重新读取修改后的主 Skill、相关参考及受影响说明，确认条件路由、补读/停止条件、权限和版本边界一致。运行 `pnpm lint` 及本次适用的本地路径/资源/分发检查，检查 `git diff --check` 和新增文件。按本次授权区分静态检查、案例执行与真实宿主观察，不把全套含案例的命令当必然可运行。
7. 在独立临时目录核对导出候选：四个 Skill、实际 Markdown 资源、版本注入、源码 `tests/` 排除与既有分发限制正确。外部 URL 可读、源树路径正确、包内文件齐全、目标宿主实际加载和模型行为分别报告；没有实际证据的项不称通过。

若要采用新上游版本，先核最新发现入口及实际差异，再固定新的 Commit/版本并同步相关路径、依赖和适配；不要只把链接中的 SHA 批量替换。本任务只做结果 Review、格式/路径/资源/分发等确定性检查，不运行案例、模型评测、任务模拟或证明器；之后的维护遵循当次授权。

## 旧 `kgos-ontologies` 处理

独立官方业务模型产品线与运行时发现/同步入口已退出当前源码合同。远端仓库及历史 Tag 保留原状；VLog/AIMemory 的固定历史链接位于基础本体入口，只在具体对照需要时读取，不安装模型或旧领域 Skill。

- 当前 VLog 可维护模型与查询在 `plugins/kgos/skills/kgos-vlog-standards/references/`，历史来源 URL 留在文件中；后续修订在本仓库维护，不再由旧库覆盖。
- `scripts/sync-vlog-ontology.mjs` 保留为安全失败入口，说明退役位置；不会读取旧库或覆盖文件。原旧库导出工具仅属于其历史工作流，当前安装不调用它。
- 已采用旧模型、已有私人 Memory Skill 与用户定制按其真实来源识别。需要迁移时比较目标 State 的本体、身份、关系与实际 Knowledge，取得具体方案授权；源码更新不自动迁移。
- 远端旧库的退役说明、归档或删除属于独立跨库操作；本任务没有执行。

## 历史与恢复

D121 的原件包及此前 Review 证据留在本 PR 的 Git 历史和 Phase 27 历史节中，当前版本不再运行其原件清单/hash 检查或要求按旧清单安装。恢复源码或某份历史材料时，先明确所需 Commit/版本及恢复范围，核对真实差异，不覆盖并发用户改动。已发行 Plugin 从对应发行包恢复，源码回退不自动修改账户安装。

本次没有修改 Prod/Dev Ontology、Knowledge、Branch 或配置，不涉及数据恢复；Git 或镜像回退不能代替数据库回滚。提交、推送、合并、发布与部署各自报告实际结果；draft PR 不等于已发行或已安装。
