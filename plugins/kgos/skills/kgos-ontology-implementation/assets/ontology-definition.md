## 自检清单

### 一、目标与范围

- [ ] **目标覆盖**：逐一检查“典型问题”涉及的对象、关系和必要条件，模型均有对应定义；无法表达的问题不标记为通过。
- [ ] **范围控制**：模型中的每个节点和关系都能说明与目标或典型问题的关联；超出约定范围的内容已移除或经用户确认保留。

### 二、节点

- [ ] **概念清楚**：每个节点都有定义和边界；用正例、反例检查，能与容易混淆的其他节点区分。
- [ ] **类型与实例**：逐一检查节点代表的是一类事物还是具体事物；没有把具体实例误当成节点类型，也没有把类型误当实例。
- [ ] **上下位关系**：逐一检查每条上下位关系；下级的实例必须都属于上级，不能仅因为名称相近或方便分类就建立继承。
- [ ] **身份与变化**：对需要区分身份的对象，用实例检查“何时是同一个对象、何时是不同对象”；对象发生状态变化时，身份和相关关系仍能按设计表达。

### 三、关系、属性与约束

- [ ] **关系语义**：逐一检查关系的起点、终点、方向和成立条件；用正例和反例判断关系是否成立。
- [ ] **数量与时间**：对需要限制数量或记录时间的关系和属性，检查限制是否符合实际场景；不需要的标记为“不适用”。
- [ ] **约束一致**：检查相关节点、关系、属性和规则组合后是否矛盾；构造符合规则的例子，并用不应成立的例子检查限制。
- [ ] **属性归属**：每个属性的含义、所属对象和取值要求明确；描述现实的语义约束与未来平台的字段配置不混为一谈。

### 四、参考依据

- [ ] **参考本体使用**：列出实际采用的参考本体和版本，对照其定义检查映射的概念和关系；对不采用或调整的部分说明理由，不把相似名称直接视作语义相同。

### 五、场景验证

- [ ] **典型问题**：针对每个典型问题，准备具体实例与关系，说明模型如何表达并得到预期答案；不能依靠模型之外未给出的信息补全答案。
- [ ] **边界与反例**：至少针对容易混淆的关键概念、关系和规则，检查正常情况、边界情况与不应成立的情况，并记录结果。

### 六、交付与变更

- [ ] **图与定义一致**：图中的节点、关系均有对应定义；定义中的节点、关系也已反映在图中。
- [ ] **修改影响**：修改已有本体时，核对新增、修改、删除项，以及保留概念是否发生语义变化；列出受影响的原有概念、关系和实例。不涉及修改时标记“不适用”。
- [ ] **用户确认**：需要用户决定的问题均已确认，模型已按确认结果调整；没有影响本次交付的未解决问题。
- [ ] **结果完整**：上述检查均记录检查对象及结果；未通过的项目已修正并重新检查，不适用的项目说明原因。

每项记录检查对象、结果和简短依据。结果使用“通过／未通过／不适用”。需要确认或无法检查时，不勾通过，先处理后再交付最终版。
