# Claim 阈值判断教学例

本例只作纸面演示，不执行写入。模型依据是已在固定 State 中实际读取并核对的 KG OS 定义；公共教学材料不包含该私有实例的 State 标识。这不是所有分支通用的字段表，也不保证未来目标分支仍使用相同定义。真实任务仍须读取自己获授权的目标 State。

本例已核对 `node:Claim`、`node:Source`、`node:Observation`、`node:SoftwareVersion`，以及 `CLAIM_BASED_ON_OBSERVATION`、`CLAIM_EVIDENCED_BY`、`CLAIM_ABOUT`、`OBSERVATION_SOURCED_BY`、`OBSERVES` 的完整定义。


教学材料：

“运行记录 R-17 显示：服务 A 的 v2.4 在并发 20、持续 5 分钟的测试中，p95 为 420 ms。要求文档 Q-3 规定，同一条件下 p95 不高于 500 ms。未检查错误率和资源占用。”

## A. 输入、候选与已有对象

使用上述 R-17、Q-3 教学材料。待处理候选是：据 R-17 报告，服务 A v2.4 在该次并发 20、持续 5 分钟的测试中，p95 为 420 ms；与相同条件下 Q-3 规定的 500 ms 上限比较，该项报告值满足阈值。

以下为教学情境的明确前提，不声称这些实例真实存在于上述 State：

- 已成功读取并核对 R-17 与 Q-3 的具体材料版本；两份材料明确指向同一服务版本和相同测试条件。
- 相关业务身份、重复主张及冲突已经检查，没有发现需要用户取舍的问题。
- 已有对象 `V` 是对应的 SoftwareVersion；`O` 是该次来源报告的 Observation；`S_R`、`S_Q` 分别是 R-17、Q-3 对应版本的 Source。
- `O` 的实际正文保留 `basisKind = source-reported`、报告值、测试范围及未检查项；已存在 `O → S_R` 的 OBSERVATION_SOURCED_BY 和 `O → V` 的 OBSERVES，且都已核对内容及端点。
- 若后续真实执行，用户授权必须明确覆盖新增该主张及下述三条关系；本例本身不提供授权。

`V`、`O`、`S_R`、`S_Q` 和下文的 `C` 只是教学说明别名，不是 KG OS 永久 Ref，也不是 SDK 请求别名。实际变更须使用读取结果及创建结果返回的真实 Ref。若已有对象或关系不存在，须另行整理所缺内容及授权，不能把本例前提当成查询结果。

## B. 候选映射到必需字段

该 State 的 Claim 明确声明六个 `required: true` 属性：attribution、claimKind、epistemicStatus、lifecycle、scope、statement。claimKey 另有 `key` 约束，不能因为没有重复写 `required: true` 就遗漏身份键。以下归属及认识状态按这个固定模型的明确要求填写，不是所有知识都要增加的 AI 身份标签。若真实目标仍采用这些要求，不得省略；若模型不同，按真实定义映射，不照搬字段。以下是教学赋值，不是可直接提交的 canonical Patch：

- `claimKey`：`teaching:assessment:service-A:v2.4:R-17:Q-3:p95`。用于演示该独立判断的身份，不是生产命名规范。真实实施须沿用目标世界的身份约定并查重，不使用这个教学键。
- `attribution`：`助手依据 R-17 的来源报告及 Q-3 的阈值要求作出的比较推断；未独立复跑测试。`
- `claimKind`：`conclusion`。该值已在上述固定 State 的 Claim 实例中实际使用，本例沿用它表示这次阈值比较结论；它不是 KG OS 提供的数据库枚举常量，也不表示所有分支都采用相同分类。不能用 inferred 代替业务类别。
- `epistemicStatus`：`inferred`。标记该比较结论的认识状态，不把来源报告升级为直接观察。
- `lifecycle`：`active`。仅表示教学情境中拟采用这条记录，不证明主张已经独立验证，也不证明适用到未来测试。
- `scope`：`服务 A v2.4；R-17 报告的并发 20、持续 5 分钟测试；仅比较 p95 与 Q-3 同条件阈值。未检查错误率、资源占用及其他验收条件，不适用于生产环境或后续测试。`
- `statement`：`据 R-17 报告，该次测试的 p95 为 420 ms，满足 Q-3 在相同条件下规定的不高于 500 ms 的阈值；这不代表全部性能验收通过或已决定上线。`

另使用实际存在的可选属性 `rationale` 保存依据：

`R-17 提供该次报告值，Q-3 提供相同对象和条件下的阈值；420 ms ≤ 500 ms，因此仅得出该报告值满足该项阈值。测试结果未独立复跑，其他指标未检查。`

本例不填写 validFrom、validTo 或业务发生日期，因为材料没有给出这些值。也不为方便检索而给 Claim 添加 confidence、sourceId、evidenceType 等未在本例中核实和约定的属性。

## C. 关系与证据的位置

新增主张说明别名为 `C`，计划建立三条关系：

1. `C → O`，关系为 `CLAIM_BASED_ON_OBSERVATION`。
   - 该关系的实际起点是 Claim，终点是 Observation。
   - 必填 `basis`：`O 保留 R-17 的 p95 报告值 420 ms；与 Q-3 的同条件 500 ms 上限比较形成本结论。该观察只支持这次报告值，不支持整体性能通过或因果判断。`
   - 可选 `scope`：`仅 R-17 的该次测试和 p95 指标。`
2. `C → S_Q`，关系为 `CLAIM_EVIDENCED_BY`。
   - 该关系的实际起点是 Claim，终点是 Source。
   - `evidenceRole`：`阈值要求来源`。
   - `evidenceScope`：`Q-3 支持相同服务版本和测试条件下 p95 不高于 500 ms 的要求；不提供 R-17 的实测结果，也不证明全部验收通过。`
   - `locatorDetail`：本例省略此可选属性，因为教学材料没有提供页码或行号。真实任务如已取得可核对的位置或片段定位，可以按实际内容填写，不编造位置。
   - 该定义还提供 `use`，本例无需为凑齐字段重复填写同样说明；若更新已有关系，不能因此删除原 use 中仍有用的依据。
3. `C → V`，关系为 `CLAIM_ABOUT`。
   - 起点是 Claim；该 State 的定义文字明确允许 SoftwareVersion 作为所谈论的对象。
   - `basis`：`两份已核读材料均明确指向该服务版本，结论只讨论它在 R-17 中的该次测试。`
   - `scope`：`服务 A v2.4 在 R-17 测试中的 p95 阈值比较。`

保留并核对现有证据路径 `C → O → S_R`。其中现有 `O → S_R` 的 OBSERVATION_SOURCED_BY 必须已有定义要求的 evidenceRole、evidenceScope，并保留 R-17 的来源归属及范围；`O → V` 的 OBSERVES 必须指向同一个版本。若这些前提缺失或不符，不能只补 C 的文字然后宣称证据关联完整。

Q-3 通过主张的来源关系支持阈值，R-17 通过观察及其来源路径支持报告值，两种作用分开。不要给两份来源都写“支持结论全部内容”。

## D. 变更清单

假设以上前提及实际授权均已满足，清单应为：

- 目标：实际获准的 KG OS 实例与分支；本例固定 State 仅用于说明模型，真实执行前重新读取目标分支的 Head 并核对变化。
- 新增：一个 Claim `C`，保存上面七项必需身份与内容字段，以及 rationale。
- 新增关系：C → O 的 CLAIM_BASED_ON_OBSERVATION；C → S_Q 的 CLAIM_EVIDENCED_BY；C → V 的 CLAIM_ABOUT。
- 复用：V、O、S_R、S_Q 及已经核对的 O → S_R、O → V；不重复创建来源、观察或版本。
- 不调整：既有知识的身份、生命周期、上线决定或其他验收结果。
- 保存前再核对：目标身份及来源版本仍对应；同一判断没有被其他操作新增；不存在新的冲突或必要联动。
- 操作结果要求：获取新 Claim 与三条关系的实际 Ref 和实际保存 State，供回读使用；不预先猜测这些 Ref。

若保存前发现同一主张已经存在，转为复用并核对证据是否需要补充，不仍按“新增一个节点”执行。

## E. 回读判据

回读实际保存 State 中的结果及相关已有对象，逐项核对：

- 新 Claim 的六个 required 属性、claimKey 及 rationale 与本次获准内容一致。
- claimKind 表达业务类别，epistemicStatus 表达推断状态，lifecycle 没有被解释成真实性；三者没有混用。
- 三条新增关系的实际起点均为新 Claim，终点分别为 O、S_Q、V，方向、属性和证据范围正确。
- CLAIM_BASED_ON_OBSERVATION 的必填 basis 已保存，且没有把观察结果扩大成整体验收或原因结论。
- 复用的 O → S_R、O → V 仍正确，R-17 和 Q-3 的来源版本未被混淆；没有重复创建另一份相同观察、版本或主张。
- 用“该次 p95 是否满足阈值、依据是什么”检查时，答案能返回报告值、阈值、两种证据作用和适用条件。
- 用“是否全部性能验收通过或可以上线”检查时，答案保留未检查项，不能推出全部通过或上线决定。

上面检查全通过，只支持“该候选按核对过的模型正确保存，并通过这些问题的使用检查”。不支持“测试已独立复跑”“生产环境性能已验证”或“其他分支可以沿用同一字段表”。
