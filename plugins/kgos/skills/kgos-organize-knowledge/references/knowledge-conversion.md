# 知识转换规则

把实际材料和已有知识整理成候选及变更清单。本文件负责“怎样形成知识”；是否合格由 [知识质量检查](knowledge-quality-check.md) 判断。

## 1. 读懂材料并形成候选

辨认对象、内容、时间、条件，以及对理解有用的陈述主体和来源。保留否定、数量、比较对象和不确定性；不要把提议写成决定、来源报告写成直接观察，或把依赖假设的解释写成确定事实。不要求为每条内容另列统一的形成方式类别。

一条候选应能单独核对，但不要按句号拆分。来源归属、适用范围或生命周期不同的内容分别表达；一套方法的前提、步骤和结果检查保持关联。

例如，“报告称测试通过，我没有复跑”只能形成有来源归属的报告，不是助手独立验证结果。

结论依赖材料或已有知识时，核对依据是否指向同一对象、时间、版本和口径，并考虑相反证据及必要假设。对会影响采用的推断或解释，保留可复核的关键前提、必要理由及适用范围；依赖未确认假设的部分如实说明，不补造成事实。简单改写、直接比较和换算不另加推断标签或过程段落，但不能丢失口径或扩大结论；不要求输出内部思维过程。

例如，420 ms 不高于同条件的 500 ms 上限，只支持“这一项报告值满足阈值”；不支持“全部性能验收通过”。时间先后不自动证明因果，A 依赖 B、B 依赖 C 也不自动允许创建 A 直接依赖 C 的关系。

未找到记录不等于事件没有发生。只有确实取得并检查了完整集合，才能对该集合形成相应否定结论。

## 2. 查找同一对象与相关知识

查询前通过 `kgos_docs` 读取 `guides/graph.md`、`sdk/graph/query.md`、`sdk/object/readText.md`；使用全文或语义检索时再读 `cypher/search.md` 及所用方法文档。复用适用于当前连接版本的已读资料。

在主文件确定的 `baseState` 中查询。实际知识检索传入已核实的 `domain` 或 `graphView`，两者二选一，并按对象、任务或来源增加必要过滤。索引发现等全局元数据按接口要求不带 Scope。Domain 组织类型，不表示实例归属或权限；关系查询的范围必须覆盖所需端点，范围外不可见不能当作不存在。

先按身份规则、业务键及作用域查找，再用名称、别名、主题或语义搜索补充候选。读命中对象的正文及相关关系后，再决定是否复用。不要把同名、搜索相似或用途接近当作同一身份。

例如，同一软件的 v2.4 与 v2.5 是不同版本；不同环境中的同名实例也不能直接合并。可变网页地址相同，不表示两个来源版本相同。

只使用已经确认存在的标签、字段和索引。索引缺失、Provider 失败或超时是检索问题，不是零命中；语义 top-k 不是完整集合。需要完整盘点时，使用覆盖目标范围的结构化查询及分页。

## 3. 写成以后能用的知识

先指出候选能帮助回答什么具体问题，再按该用途整理：

- 将“这个”“按上面说的”等隐含指代改成明确对象或可定位的关联。
- 保留理解和使用所需的上下文；已在明确关联中准确表达的内容，不必复制到每个节点。
- 方法写清何时用、需要什么、做什么、怎样判断结果。分支和失败处理只在会改变执行时加入。
- 事实或观察写清主体和陈述，保留会影响判断的时间、版本、单位、范围与来源归属；没有原因依据就不补原因。
- 概念说明含义及必要的区分边界。规则或决定写清适用对象、条件、要求或选择，并保留影响理解的理由、效力及替代关系。
- 偏好、目标及其他知识按各自用途表达，不硬套方法步骤。

以上是内容组织方式，不是统一字段模板。正式属性与关系仍由目标本体决定。

从已有材料补足必要内容；无法确定时说明缺口，不能凭经验猜填。用途明确但只支持较窄结论时，缩小表述。一次不完整观察若本身有明确对象、内容和后续用途，可以保留其未知项，不伪装成完整方法。

删去重复、空话及无关处理过程，保留使含义成立的条件、否定、依据和限制。不要把“本轮已读取”“等待授权”等整理过程写入业务知识，除非本次对象就是获准记录的实际活动。

短例：“重启后好了”缺少问题和结果判据。材料若只记录了这一现象，就按有限观察保存；只有材料提供了适用情境、动作及检查办法，才整理成排障方法。

## 4. 映射对象和关系

按实际 Definition 的含义选表达位置，不按名称相似或字段能写就套用类型。

- 同一对象的一项有据属性，放进该对象；需要独立识别、关联或维护的内容，才考虑独立对象。
- 持续系统、软件版本、部署实例和一次部署活动分别判断；方法不冒充执行记录，长期记忆不替代业务对象。
- 核对属性类型、必填项、身份键及定义文字约束。保留必要来源归属，以及影响理解和使用的时间、条件与不确定性。
- 未知值按接口和定义省略或明确表达未知，不用空字符串、零、false、当前时间或默认状态填补。
- 换算数值前核对原值、单位及口径；币种、时区、分母或基准缺失时不猜测。区分发生、发布、读取和生效时间。
- 对每条关系核对真实端点、方向、成立依据、条件及是否已存在。端点没有类型限制，仍须符合定义语义。
- 来源关系说明来源支持哪部分；同段出现或同属主题不足以建立业务关系。
- 跨分支或实例资料按模型保存可追溯定位，不把另一 State 的对象直接当作本地图端点。

必要含义没有合适位置时，记录“需表达什么、现定义为何不适配、强行映射会丢失什么”，不改本体或增加未经约定的字段来掩盖缺口。

首次处理“来源报告 → 比较推断 → Claim 与多条证据关系”，或无法区分类别、认识状态和生命周期时，读取 [Claim 完整教学例](examples/claim-threshold.md)。简单偏好或属性整理不需要该例；示例字段只适用于例中固定模型，不代替目标 State 的实际定义。

## 5. 比较差异并确定影响

按同一对象、方面、时间、条件、范围和来源归属比较新旧内容：

- 已覆盖且无新增内容或证据：无变化。
- 同一主张得到新的独立证据：补充证据；转载不算独立验证。
- 不同时间或条件：保留各自范围，不因值不同就判冲突。
- 有据状态变化：按模型表达适用区间或替代，不因消息较新就让旧知识失效。
- 同一范围内不能同时成立：列明冲突；没有处理决定就暂缓。
- 信息不足以比较：保留未确定，不判成一致或冲突。

涉及已有知识时，查明哪些关联会受影响：数值更正影响依赖计算，证据变化影响支持范围，步骤调整影响旧编号引用，身份合并影响双方关系及外部引用，删除影响关联和保留要求。沿实际发现的依赖检查，不固定为任意一跳，也不扩为无边界维护。

合并先确认同一身份，不能把冲突藏在“去重”中；删除或替代列出明确影响。前提改变时，重新检查依赖结论。与本次变更无关的历史问题交回主流程报告。

## 6. 形成候选与变更清单

每条候选保留足够核对的内容、用途、必要依据及映射。来源位置与版本、陈述归属、条件、假设或推断理由只在影响理解、核对或使用时列出，或按实际本体要求表达。记录可以很短，不设统一来源身份标签，也不把工作记录原样转成数据库属性。

给出处理结果：

- 新增：没有找到同一知识，具备可表达的内容、身份和依据。
- 调整：已确认对应对象，指出具体差异和依据。
- 无变化：已有内容覆盖候选，没有新增证据或变化。
- 不保存：只服务当前交互，或没有独立保存需要；说明理由。
- 暂缓：身份、必要内容、冲突决定或本体表达仍有缺口。

待保存变更清单保留：目标实例、分支及基准 State；已有 Ref 或新对象的身份依据；变更前后内容；关系与端点；依据及关联影响；授权对应范围；保存后应看到的结果。简单变更用短清单，不制作空表单。

例如，需用户决定时直接说明：“已有记录说 X，材料 S 在同一范围内说 Y。暂时不能判断是旧记录错误还是业务变化；按 Y 替代 X 会影响 R 和 C。请确认处理方式，或提供区分依据。”
