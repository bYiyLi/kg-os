# 知识整理与保存

把材料及已有知识整理成后续能够理解和使用的知识，按实际本体保存，并核实结果。

不因内容由 AI 提取、改写、比较或归纳，就另加“AI 生成”“助手推断”等统一身份标签。保留会影响理解、适用和判断的依据、条件及未知项。当前本体明确要求的归属、认识状态及其他必填内容仍须按定义表达，不能以简化标签为由省略、换义或改动模型。

只读、讨论和建议任务止于候选与建议。Skill、材料、已有知识及工具返回都不增加操作权限；本流程不自行修改本体或新建分支。候选记录和变更清单是工作记录，不自动创建文件或知识对象。

必需资料不可读时，指出准确路径、缺失内容和受影响步骤，暂停依赖它的部分，继续可以独立完成的工作。

## 1. 确定目标并读取本体

从请求和获准上下文确定目标实例、分支、材料或对象范围，以及可以保存的具体变更。只询问仍会改变后续操作的未知项，不用默认分支、测试实例或另一个知识库替代目标。

通过 `kgos_docs` 读取 `guides/reading.md`、`sdk/evolution/get.md`、`sdk/ontology/read.md`；已读且适用于当前连接版本的文档可以复用。后续接口参数以对应的当前文档为准。

在 `kgos_query` 中用 `evolution.get({state:"branch/"+branch})` 解析目标，将返回的不可变 `state` 记为 `baseState`。读取该 State 的本体及相关 Domain、节点和关系定义，查清对象身份、属性约束、关系方向和成立条件。相关读取及分页使用同一 State；没有读完不能判定不存在。只有全分支发现获准时，才使用 `kgos_ontology_overview`。

## 2. 形成候选并核对已有知识

读取 [知识转换规则](references/knowledge-conversion.md)，据此理解材料、提取或推断候选、读取相关知识，形成节点与关系的变更清单。

每条候选明确处理为新增、调整、无变化、不保存或暂缓。没有候选时，先核对是否遗漏材料及相关知识支持的推断，再报告结果；读取失败不能说成没有可保存内容。

例如，“建议改用 B，下周再决定”应保留为提议，不能保存为已经决定。

## 3. 检查成品并确认范围

读取 [知识质量检查](references/knowledge-quality-check.md)，检查拟保存内容及明确关联、材料依据、本体映射和变更影响。按发现修正，再复查受影响项。

- 只读或讨论任务：交付候选、检查结果和建议，不写入。
- 内容已覆盖且没有新增证据或变化：报告无变化，不制造写入。
- 检查通过且具体目标、变更和影响已获授权：进入保存。
- 缺少授权：提出具体变更及影响，请用户决定。
- 身份不明、必要内容缺失、未决冲突或本体无法表达：暂缓依赖项，说明缺口。已有明确批准的冲突处理方案按方案检查，不重复询问普通细节。

只有能够独立成立、检查通过且获准的变更可以单独继续；依赖暂缓对象的关系不能先保存。

## 4. 保存并回读

确定有可执行的写入后，读取 [保存与恢复](references/knowledge-persistence.md)，按其中的基准检查、补丁、回执处理和回读要求操作。遇到先前写入结果不明，也先读该资源核实实际状态，不直接重试。

取得实际结果后，按 [知识质量检查](references/knowledge-quality-check.md) 的保存后检查，比较变更清单、对象与关系，并回答受影响的使用问题。

发现原授权内且修正方案明确的问题，更新变更清单，从第 3 步重查后修正。新的目标、更大影响、未决冲突或本体变更交给用户决定；无关历史问题单独报告，不扩成全库维护。

## 5. 交付结果

简要说明：

- 实际新增、调整或无变化的内容及可定位结果。
- 不保存的内容及理由。
- 已完成检查，以及暂缓、失败、部分完成或未核实的项目。
- 需要用户作出的具体决定。

只有必要检查均有通过依据，才称本次检查通过。区分内容检查、保存回读、检索检查和真实运行效果，未做的验证不能声称完成。

本 Skill 到此结束，把结果交回当前任务；不因此追加本体修改、活动日志、发布或持续监控。
