# 知识质量检查

检查已保存的知识内容及其明确关联，不以字段齐全、工具接受或来源存在代替内容质量判断。本文件给出通用内容要求；具体类型、属性、身份与关系约束以目标 State 的实际 Definition 及已确认领域要求为准。要求冲突而无法消解时，不作确定合规判断。

以下八组覆盖本 Skill 的检查范围。按实际内容选择第 4 组的类型项，其余组逐项判断适用性。条目是内容判据，不是新增数据库字段或要求所有知识采用相同结构。例子均为构造例，用于区分判定边界，不代表库中现状或字段约定。

## 1. 内容完整

对象、陈述及适用范围应足以理解；保留会改变含义或判断的条件、时间、版本、例外、否定和限制。

- 关键内容能在正文、属性或明确定位的关联知识中读到，不必回到未关联的原聊天或靠猜测补齐。
- 不能用“按上文执行”“处理后恢复”等不明指代代替必要对象、动作或结果。
- 已知关键内容未表达属于内容缺口；内容可能在不可访问的关联中时，记为未核实，不直接认定缺失。
- 有独立用途的有限观察或线索可以合格，前提是明确实际知道什么及不知道什么，不冒充完整方法或已验证结论。
- 来源或索引对象只保存定位信息可以符合其用途；自称完整方法的对象不能仅靠一个未展开链接证明方法内容完整。

正例：“服务 S 重启后，该次请求返回 200；未检查其他接口，也未确认原因”可作为有限观察。
反例：同一内容被表述为“所有异常均已解决”，其范围超出已有结果。

## 2. 表达清楚

术语、指代和陈述主体应可识别；区分不同对象、动作、状态及认识程度。

- 数量、单位、比较基准、分母、币种或时区，仅在影响含义时要求明确；不为没有时间含义的概念强加日期。
- 区分发生、发布、读取和生效时间，区分软件版本、方法版本、来源版本与记录 State。
- 影响理解或采用的来源归属、假设、争议和未知应可辨认，不要求所有知识都有统一的来源类别、AI 身份标签或专用状态字段。当前 Definition 明确要求的必填项及语义仍须核对，不能因本条而豁免。状态标签按定义理解，不从“active”推导真实、有效或已验证。
- 文字与属性、正文与关系之间不能表达互不兼容的确定含义。

正例：“报告中的本次响应耗时为 420 ms，阈值为同口径的 500 ms。”
反例：“性能是 420，比 500 好”，但无从确定指标、单位和比较口径。

## 3. 内容简洁

每段内容应承担对象识别、必要内容、条件、依据、限制或理解辅助中的实际作用。

- 找出同义重复、空泛评价、无关处理过程及与知识用途无关的内容；问题须指明具体冗余，不凭长度判错。
- 不把“本轮已读取”“等待授权”“没有新增关系”等整理过程混入业务知识，除非对象本来就是实际活动记录。
- 不因追求简短而把必要前提、否定、证据归属、失败条件或限制判为多余；长方法不因步骤多就不合格。

正例：保留“仅核对文档，未在目标环境运行”，因为它限定证据。
反例：在同一方法中重复三次“本次已认真检查”，但未增加检查内容或范围。

## 4. 符合实际知识类型

先按当前定义及内容判断它表达什么，再检查对应的必要内容。以下是常见内容类型，不是完整的本体分类，也不据此强制新建类型。同一对象含多种内容时分别检查；不适用的项目不硬套。

### 方法

应明确解决什么问题、何时适用、执行所需前提、关键动作和结果判据。会改变执行的分支、失败条件与限制应可识别；动作的对象及必要输入不能靠猜测。仅在用途需要时要求具体顺序，不要求所有方法固定编号。

正例：排障方法说明目标症状、必要权限、具体检查及何种结果可排除某项原因，并保留未经验证的范围。
反例：“遇到问题先分析，再采取有效措施，最后确保成功”，没有可执行动作或判据。
尚未证明普遍有效不自动等于方法内容不合格；若内容声称实测有效，则另按第 5 组核对证据。

### 事实、观察及来源报告

应明确所指对象、发生或报告的内容，以及会改变判断的时间、版本、范围、单位和来源归属。观察者、来源报告与转述者不能混为一人；未知原因无需补造。

正例：“来源 A 报告版本 V 的测试 T 通过，记录者未复跑。”
反例：没有新增证据，却把该内容写成“已独立验证版本 V 全部测试通过”。

### 规则与决定

规则应能识别适用对象、条件和要求；决定应能识别决定主体、已作出的选择及适用范围。已知且影响效力的时间、例外、理由或替代关系应保留。不把提议、计划、愿望或一次执行当作已生效规则或既成决定。

正例：“负责人决定项目 P 本次发布采用方案 B，仅适用于版本 V。”
反例：“建议采用 B，下周讨论”被记成“项目已经决定全面采用 B”。

### 概念、实体及分类

概念应能辨认含义及容易混淆的边界；实体应有符合定义的身份及足够区分的信息，不能仅以同名推导同一身份。分类关系须符合其含义，不把类别当一次实例，或把主题相近当所属关系。

正例：软件系统、部署实例和一次部署活动按各自定义表达。
反例：同名的两个环境实例被当作同一实例，仅因显示名称相同。

### 偏好、目标及其他内容

偏好应明确谁在什么范围偏好什么；目标应明确主体与期望结果，已表达且影响理解的期限、优先级及条件应保留。不要求简单偏好附执行步骤，不把一次选择自动扩大为长期偏好，也不把目标当已实现事实。

其他类型按其当前定义和合理用途检查，不为凑齐上述项目强行改类。活动记录重在实际发生内容与结果边界；案例重在情境、行动及可取得的观察，不要求资料分析案例伪造实际实践。

## 5. 陈述与依据相称

逐项核对陈述归属、前提和支持范围；区分“来源这样说”“记录者观察到”与“现实中已经成立”。

- 不把提议升格为决定、局部指标升格为全部验收、教学示例升格为真实实践、时间先后或相关性升格为因果。
- 依赖假设、多个前提或存在争议的结论，应保留可复核的关键依据、口径与必要理由；不得用降低置信分数掩盖缺失前提或越界结论。简单改写、直接比较或换算，不因缺少单独的“推断”标签或推导段落而判错。
- 来源关系应能说明支持哪部分内容；引用、转载、工具成功或内容写得清楚都不自动证明真实或效果。
- 必要的反例或相反证据不能被确定陈述忽略；若陈述已经准确表达争议与限制，不因结论未定判错。
- 原文无法访问时，区分“尚不能核实转述是否准确”和“已有内容已显示越界”。前者是未核实；后者可成为确定问题。无法独立验证现实真实性，不等于有归属的来源陈述没有记录价值。

正例：“同一条件下，420 ms 不高于 500 ms 阈值，仅此指标满足要求。”
反例：由同一前提推出“系统全部性能验收通过”。
边界例：来源失效只能使原文核对受阻；正文把“建议”写成“已决定”，且可读的引用片段明确保留“下周讨论”，仍有可核对的认识状态冲突。

## 6. 符合实际本体

逐项核对知识所用节点类型、属性、必填项、类型约束、身份键及 Definition 文字约束。

- 类型所指对象和知识内容相符：方法不是一次执行，来源不是它所描述的业务对象，生命周期不等于证据强度。
- 必填字段存在还须核对其内容含义；空话、占位值或不适用值不能满足实际要求。未知值的表达依定义和接口判断，不凭零、空字符串或当前时间推断真实状态。
- STRING 中的状态约定、模型文字中的基数与条件也要检查，不假定数据库已经替使用方完成语义验收。
- 不把模型未声明某个属性直接判为错误。通用属性图可能允许额外属性；只有违反实际 Schema、明确约束或语义要求时才报告问题。
- 知识与模型不匹配时指出具体冲突；模型自身矛盾或无法确定含义时，保留受影响判断为无法确认，不把本体问题归罪于知识。

正例：方法生命周期为 active，同时明确效果尚未独立验证，两者可以相容。
反例：仅因 active 就把该方法记录为“已证明每次使用成功”。

## 7. 关系成立

对目标知识的实际关系核对端点身份、方向、类型、语义、条件及支持范围，并读取判断所需的端点内容。

- 同段出现、同属主题、同名或搜索相似不足以建立业务关系。
- 来源引用、实际采用、执行发生、结果验证及因果关系分别判断，不互相替代。
- 端点没有 Schema 类型限制，也必须符合定义文字中的语义范围。
- 必要关联以实际定义或内容用途为依据；只有读取覆盖所需端点和关系时，才能确认缺失、基数违反或指向错误。
- 他分支或他实例的 Ref 不能未经核对当作当前 State 中的同一对象；跨范围资料按实际模型的可追溯引用方式判断。

正例：案例“示范了方法 M”可以是教学使用，不证明 M 在真实场景有效。
反例：仅因案例提到 M，便记录“该案例独立验证了 M 的效果”。

## 8. 与相关知识一致

比较对象身份、方面、时间、版本、条件、范围及来源归属，再判断差异。

- 同一范围内不能同时成立的确定陈述才构成冲突；不同日期的价格、不同版本的行为或不同主体的偏好不因值不同而冲突。
- 不因内容较新就认定旧知识失效；替代、终止、纠错和真实变化须分别有据。
- 重复记录按身份和独立用途判断，不以同名、同句或相似度直接判重复。历史快照、来源归属不同的报告可有各自用途。
- 沿实际关系检查依赖内容是否仍相称，如结论与前提、正文与来源位置、步骤编号与引用；只在既定审核范围内继续，不扩成无边界维护。
- “不存在”“全部一致”“没有重复”等结论只覆盖确实成功读完的集合；范围外或不可访问内容保持未知。

正例：同一挂牌在不同日期有两个价格快照，并标明各自来源和日期。
反例：两个记录对同一时间、同一房屋、同一价格口径给出互斥的确定价格，却没有区分来源争议或更正关系。
