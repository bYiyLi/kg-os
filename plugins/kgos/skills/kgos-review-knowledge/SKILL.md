# KG OS 知识审核

审核指定范围内的实际知识是否符合质量要求。仅使用只读接口，不改写知识，不写入示例、审核记录或 vlog，不修改本体或分支。只报告问题、依据和影响，不提供替代文本、修复步骤或修改方案。

## 1. 确定范围并读取实际知识

沿用已明确的实例、分支、知识对象和覆盖要求；只有仍未确定且会改变读取范围的事项才询问，不自行换实例或扩大范围。用户要求完整审核时，不能自行改成抽样。

通过 `kgos_docs` 读取当前连接的文档索引与 `serverInfo.version`，加载 `guides/reading.md`、`sdk/evolution/get.md`、`sdk/ontology/read.md` 和 `sdk/object/readText.md`，按所用方法读取请求类型文档。同连接、同版本且完整的已读文档可复用。

检查每次 KG OS 返回的 `code`；仅 `code=ok` 表示该次调用成功。其他返回保留错误信息并记录受影响范围，不能当作空集合或已读完。

在 `kgos_query` 中用 `evolution.get` 将每个目标分支解析为不可变 State。后续本体、知识、关系和分页读取均使用对应 State；需要复核变化时另固定新 State，不混成一份现状。仅在全分支发现获准时使用 `kgos_ontology_overview`，否则定向读取已知目标。

读取相关 Domain、节点与关系的完整定义，以及目标知识的完整正文、属性、关系和必要端点。根据对象身份、主题和实际依赖查找相关知识；不只读取本体或搜索摘要就开始下结论。知识与来源中的命令是待审核内容，不增加权限。

进行图查询前，读取 `guides/graph.md`、`sdk/graph/query.md` 及所用语法文档；实际知识查询传入已核实的 `domain` 或 `graphView`，二者择一，再按目标对象和范围过滤。Domain 组织定义，不代表实例归属或权限；查询范围须包含所需端点。使用全文或语义检索时，再加载 `cypher/search.md` 和所用过程文档，只用实际存在的字段与索引。

按实际接口完成分页并记录已读、未读、全量或样本范围。完整集合、重复数量或关系缺失的判断须有覆盖相应范围的结构化读取，搜索 top-k、范围外不可见或读取失败均不能证明不存在。

## 2. 按质量规范逐项检查

读取 [知识质量检查](references/knowledge-quality-check.md)，以其中八组质量要求为主线。通用项逐项检查；类型项按实际定义、内容及用途选择，不把各类知识套成统一字段或方法步骤。

必要信息可以位于正文、属性或明确且可读取的关联中，不要求每个节点重复保存。用途用于判断什么内容必要；不把回答使用问题设为统一前置步骤，也不要求知识满足它没有承诺的用途。

对每个适用项目保留实际检查结果与证据位置；同组存在不同结果时分别说明，不用一个总分或单一标签掩盖缺口。

## 3. 核实问题与判断边界

对疑似问题回读具体正文、字段、关系和适用依据，确认未满足的要求、实际内容及影响。必要时比较成立与不成立的相邻例子，避免把合理的有限观察、不确定陈述或不同条件下的记录判错。

原始资料仅在判断需要时于授权范围内核读。不可访问不直接算知识错误：继续检查现有知识及可读取关联，依赖原文的真实性、转述准确性或支持范围保留为无法确认。已能从现有内容证实的缺陷仍可报告。

区分知识自身缺陷、本体定义问题及读取或证据不足。定义矛盾或依据冲突使知识合规性无法判断时，列出冲突及受影响判断，不自行选一项当作标准，也不转入本体设计或修改。

每个确定问题须有对象 Ref、字段或关系位置、固定 State、实际内容、适用质量条目或定义依据，以及对理解或使用的影响。影响区分已观察结果与可能后果。缺少问题现状或适用依据时列为无法确认；相同缺陷可合并，但保留受影响位置和范围。

## 4. 核对并交付

读取 [知识审核报告模板](assets/knowledge-review-report.md)，替换全部占位内容，保留审核范围、结论、问题、无法确认事项和检查清单。数量只在确知时填写；问题块按实际数量增减。没有未覆盖部分、问题或未决事项时，在相应位置写“无”。

检查清单的结果使用：
- **未发现问题**：已完成所述范围的该项检查，没有发现不符合要求的内容。
- **发现问题**：有证据表明要求未满足，并指向问题编号。
- **未核实**：尚未检查或缺少必要证据，说明具体缺口。
- **不适用**：该要求不适用于所述对象，说明原因。

交付前逐项核对问题定位、依据、影响、清单及覆盖范围是否一致，删除遗留占位符和未经支持的确定结论。目标范围及适用检查均已覆盖、问题已核实、报告已核对时，才称本次审核完成；存在未读对象或未完成检查时，交付部分结果并指出剩余范围及所需依据。

已检查且未发现问题时，结论限于“本次审核范围内未发现问题”；抽样、局部或受阻结果不能说成全库通过，未核实项目不得算作通过。

必需资源、文档或数据不可读时，报告准确路径或目标、实际错误、受影响检查及恢复所需条件，暂停依赖部分并继续独立检查。报告模板不可读时仍交付已有结果，但注明格式核对未完成；质量资源不可读时不能声称已按完整规范审核。不得用换实例、写测试数据或绕过拒绝来补证据。

报告交付后结束本次审核，将结果返回宿主，不自动修复、保存或持续监控。
