# 知识世界融合、生命周期与恢复

本文件指导所选世界之间的演进决策，不重新实现Merge算法、领域事实裁决或迁移器。技术一致性由实际Evolution合同执行，模型与知识含义由相应任务判断；两者不能互相冒充。

## 先明确需要哪种协作

| 需求 | 合理处理 |
| --- | --- |
| 参考另一个世界的信息回答问题 | 分别读取并保留所属库/State，不为查询先合并 |
| 只引入少量经验或某组内容 | 按目标模型识别、映射和写入所需对象；这不是整个Branch Merge，也不自动保留来源完整DAG |
| 希望一个目标世界接纳另一条演进路径 | 审查完整State差异和兼容性后，按授权使用Evolution Merge |
| 希望建立综合世界且保留两个原世界不动 | 可从选定目标基线建立新的Branch后融合；这是所需结果的一种实现，不是每次Merge强制建第三分支 |
| 两个不同物理Instance的知识迁移 | 不假定一个库的Evolution能解析另一个库的State；明确迁移和模型/身份处理范围，不假装跨库Merge |

仅仅“两个世界相关”不等于应该融合。普通边属于单个Snapshot，记录另一世界的Ref不产生跨世界实时边或自动同步；需要共享事实如何表达由实际模型及知识任务处理。全部或选择性引入的范围、目标及必要授权必须与用户意图一致。

## Merge不是简单并集

Merge处理整个State的共同祖先与变化，包括Schema、语义、知识的新增、修改和删除。来源中删除的共同祖先内容可能使目标也删除；并非“把来源现在有的东西加过来”。曾经从混合世界派生再各自清理的两个Branch，整体合并尤其需要检查删除语义。不能把 `diff(scope=...)` 误当Merge的范围选项。

同名Definition可能语义不同，不同元素也可能表示同一业务对象。底层无冲突不能证明知识不重复或两个本体相容；不要为消除冲突任意选ours/theirs、改名或丢弃字段。利用已确认的用户目标、模型/事实证据决定；需要新的实质业务选择且无法裁决时，保留该部分未决。已有授权和依据充分的选择无需重复索取确认。

## Session与实际发表结果

只读比较使用已有读取能力，不调用会持久化操作状态的 `merge.start`。完整合并授权可覆盖必要的Session建立、检查、逐批解决及finalize；“先评估是否值得合并”不等于这些写权限。Session不是Branch、Object或可供Graph读取的StateRef，不编造candidate查询入口。

开始后核对实际targetState、sourceState与session revision。source后来前进不改变Session已pin的source，不能自动把新内容纳入原批准范围。解决冲突依实际返回conflictId和当前revision，不能以path或猜测ID代替；旧冲突cursor不用于新revision。start/resolve完成都不代表Branch已前进。

finalize必须符合当前revision、目标Head及实际一致性检查。revision改变就重读受影响的解决结果；目标Head改变时，旧Session仍基于旧输入，不能仅换revision或强移Head继续，要重新比较并决定是否在原授权内重建相应工作。不要未经授权中止其它任务的Session。

核对最终实际状态：merged产生Merge Commit；fast-forward移动目标但复用来源Commit；up-to-date不移动。语义结果还需按任务检查，不由status代替；来源Branch不会因此自动删除或保持未来同步。多个操作中途失败按真实边界说明已完成与未完成，不能说整体自动回滚。

## 停用、删除与历史保存

长期未写、未合并或实验结束不构成自动删除理由。“不用这个库了”可能只是停止日常工作，先按实际任务确定是否要删除引用及是否保留历史，不把它默认为物理清除。当前没有通用archive字段或只读冻结标记，不通过改名制造权限保证。

删除Branch只移除引用；其它Branch、Tag及可达历史可能仍保留内容，独有无引用历史以后可能受实际GC策略影响。裸Commit文本不是持久保留引用，不承诺永久可读。要求保留时核实真实覆盖所需历史的引用；建立或移动Tag也须有相应授权。不要为删除一条ref顺带删Tag、其它世界、历史或运行GC，更不能将同库引用称为灾难恢复备份。

当前Branch Delete请求只有名称，没有与Object Patch等价的expectedHead条件；删除前读取Head不能保证调用时它未改变。若授权仅允许删除某个已观察且未继续前进的引用，并发仍可能发生，则不能声称已满足该条件；先取得实际可用的协调保障或保留该操作未决，不发明参数、锁或强制回退。明确允许删除该命名引用且影响范围已确认时，仍可按真实合同执行。

当前Evolution专用接口不是完整Git命令集；不要发明branch.rename/archive/reset/revert等SDK方法。底层Graph可能有额外版本能力，必须核对实际手册、权限和影响，不因为有底层入口就绕过高层拒绝。普通知识纠错通常应修正目标事实，而非回退整个世界并抹掉无关新内容；准确方法取本次授权和实际合同。

## 未知结果先观察

创建/合并/删除超时、取消或回执丢失时，先核对实际目标库、引用、State、History和相关Session；未知不等于失败，名称不存在或Session消失也不自动证明某次调用成功。确认目标已达成则不重复副作用；发生并发或同名重建时，不凭旧名称覆盖新对象。无法核实只暂停危险重复，报告已确认与未知范围。

结果检查与变更影响匹配：确认正确目标、前后State及实际内容符合要求，来源/无关引用未被本操作意外移动。仅完成比较就报告建议，不声称融合已落地；仅删除引用就报告引用删除，不声称知识已永久擦除。
