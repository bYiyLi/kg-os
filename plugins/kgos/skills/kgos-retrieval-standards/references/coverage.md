# 覆盖度、否定结论与停止判断

完整性是相对于明确问题和可观察范围的性质，不是结果条数或查询次数。区分库、State、模型/索引覆盖、过滤条件、排名候选和实际返回；一层正确不证明其它层完整。

## 全量、计数和存在不是同一任务

完整枚举需把目标范围内的匹配集合读完，或用当前接口支持且结果完整的方式取得全集。只问数量时，正确覆盖目标的聚合可直接得到计数，不必把每条正文取回；只问是否有时，确认一个匹配实例可结束，不强制遍历全集。要求列举几个示例时，满足数量和相关性即可按“示例”交付，不虚报“全部”。

计数单位可能是节点、关系、独立事件或路径。连接产生的多行不能直接算多个对象；`count(property)` 不含缺失值，不能当所有实例数。无 Label 的全图扫描也可能包含内部模型元素，不自动等于业务 Knowledge 全集。依据实际模型限定范围，而不是自己维护一个猜测的内核排除清单。

使用实际 continuation 或明确的稳定排序/分页语义；分页读取使用同一 State 和同一条件，排序并列需要适用的唯一身份作为稳定次序。更改查询/范围后不继续复用不再匹配的 cursor。Graph 行结果、Ontology cursor、MCP 预览行窗口是不同接口，不能互相套用分页参数。只看一页、达到 LIMIT 或响应被截断时，不声明已穷尽。

## Top-K 与后过滤

当前 Managed Semantic 内部 limit 先选择候选，post-YIELD WHERE 再过滤。全库前十条中只有一条属于P，不证明P只有一条，也不保证返回P内最优十条。扩大候选量可提高机会，不自动证明严格范围内 Top-K；不能省略必需limit、编造filterProperties或把 Raw Vector 内部过滤能力套给另一个 procedure。

需要严格全量或统计时，用可覆盖目标条件的读取，不靠无限放大Top-K替代完备性。需要精确范围内排名而当前可用能力不能证明时，明确限制；可交付相关候选但不得悄悄降格后仍称精确排名。多路搜索结果合并去重只扩展候选，并不自动得到统一分数或全局最优列表。

## 没找到、没有记录与现实不存在

| 观察 | 可支持的结论 |
| --- | --- |
| 有实际符合目标的记录 | 在该库/State观察到匹配对象；真实性仍取决于证据 |
| 正常完成的完整结构化检查，在定义清楚的条件下为零 | 该库/State、该范围没有匹配记录，不自动外推现实不存在 |
| Top-K、部分页、某个索引或受限权限内没有命中 | 本次方法/可见范围未找到，不能排除其它位置 |
| 字段缺失、未知状态被谓词排除 | 仅说明已知值中的结果，不能把未知当作条件不成立 |
| 缺索引、鉴权失败、Provider错误、超时或没有成功终帧 | 检索未成功完成，不是合法零结果 |

“没有未完成记录”与“所有记录都已完成”只有在范围完整、状态语义及未知值都已处理时才可能等价。例如 `status <> 'done'` 排除null，零行不能排除未知状态；同时确认目标集合是否为空，避免把空库说成项目已完成。需要现实世界否定时，还需有适用于该领域的登记完整性依据；数据库查询自己不能建立这种依据。

## 何时继续，何时停止

继续查询要指出能改变回答的缺口和可行的补齐方式：补页、精确定位候选、核对适用时间、读取相关反证或关系，而非仅重复改关键词直到出现期望答案。对存在性的一条可靠正例、对完整谓词的成功零计数、或对已满足要求的几个示例，都允许结束；不把所有问题升级成研究报告。

命中率低时可以调整词语、方法或模型范围，但不能悄悄放宽用户关键条件。遇到权限/资源/能力限制，遵守限制，不切换高权限通道或进行未授权维护来“补齐”。可解决的局部缺口继续处理；无法消除的限制以“已确认部分+未覆盖范围”返回，不无限重试或全盘拒答。

流式读取没有最终成功summary时，不能声称完整列表、精确总数或未命中。已收到的有效记录是否能支持限定的正例须看实际接口和记录完整性，并明确调用未完成；不能把一条行数据当整次成功。工具错误、日志或示例不是业务结果行。
