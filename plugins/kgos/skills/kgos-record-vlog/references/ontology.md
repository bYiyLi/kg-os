# VLog 系统活动日志本体

记录具有独立意义的实际系统活动，使后续能够分清发生了什么、涉及什么对象、结果如何以及依据在哪里。日志记录活动，不自动提炼或保存可复用知识。

## 目标与边界

**设计目标**：为 VLog Skill 提供可审阅的空库初始化模型；日常记录仍以目标库实际生效的定义为准。本文件不是一次可直接提交的 Patch，也不授权初始化或覆盖已有模型。

**适用范围**：部署升级、配置或模型变更、故障排查、重要测试验收、关键决策形成和复盘等系统活动；同一次活动的资料补充、结果更新和事实纠正。

**不包含的范围**：尚未执行的计划、普通查询和逐次工具调用的自动流水账、可复用知识提炼、独立日志质量审核、通用任务管理、跨实例图关系，以及自动证明事件真实或验证通过。

**典型问题**：

- Q1：首次部署失败、真实重试成功和后续验证，如何分别保留并正确关联？

- Q2：操作成功但验证未通过时，怎样不覆盖任何一个结果？

- Q3：同一次活动的进展、重复回执、补充证据和新的实际尝试如何区分？

- Q4：只有故障报告而未核实时，怎样记录已发生事项而不把报告当事实？

- Q5：同名系统、不同实例及改名后的同一对象如何识别？

- Q6：多份来源、材料新版本与固定证据包如何保留身份和证据范围？

- Q7：时间未知、仅知日期、长活动和重叠活动，能否正确表达而不猜精度？

- Q8：一次验证涉及多个目标且结论不同，如何避免扩大通过范围？

- Q9：已作出的决定或复盘，与计划执行、可复用知识有何区别？

- Q10：空库初始化与已有模型使用，分别需要哪些定义和检查？

Q1 的预期来自用户已确认的“有独立意义的失败、重试和独立验证分别记录”；其余预期来自当前 VLog 的事实、身份与证据边界，新增细化方案在下文明确列出。

**参考依据**：

- KG OS 0.3.16 已核对的 VLog 模型快照；公共参考不包含私有实例的 State 标识。沿用四类节点、五类关系、一个 Domain 的名称、29 个属性及类型；不声称生产库已经采用本稿补充的语义。

- [KG OS 官方 VLog 本体参考](https://github.com/bYiyLi/kg-releases/blob/v0.3.16/plugins/kgos/skills/kgos-vlog-standards/references/ontology.md)：采用逐对象 Definition YAML 格式和事件、对象、分类、来源的职责划分；核心模板不加入没有当前需求的 Time、Place。

- [UFO 2022](https://research.utwente.nl/en/publications/ufo-unified-foundational-ontology/)与 [gUFO 1.0.0](https://nemo-ufes.github.io/gufo/)：借鉴事件、持续对象、身份与参与的区分，不宣称形式化 UFO 映射或合规。

- [BFO 2020](https://github.com/BFO-ontology/BFO-2020/commit/bd1fb61c5fa4e358fc9690f0d214b1ac63fae594)：借鉴持续体与发生体、记录与所记录过程的区分；不把软件、类别或来源强行映射到单一 BFO 类型。

- 当前 `kgos_docs` 的 `guides/ontology.md`、`guides/objects.md`、`guides/reading.md` 和 `cypher/schema.md`：用于核对 Definition、类型、KEY 约束、固定 State 与实际执行边界。

### 本版提出的语义选择

以下是为审阅而提出的细化方案，不表示已获得逐项采纳或已更改现网：

1. 同一次实际活动从开始、进行到结束或中止保持身份；真正再次执行和独立验证另立事件。只更新对事件的认识，不改写已有失败为后续成功。

2. 只有未核实报告时，记录“收到报告”这一已发生事项；被报告异常的内容保留归属和未核实状态。后来确认的故障与检查分别记录，不回写成接报时已知。

3. 来源采用“有固定边界的证据单元”：可以是一份材料版本，也可以是一份明确列出组成和范围的固定证据包。包的身份不是一条可任意追加内容的活动容器。

4. 单一发生时间只表达有依据的发生时点；活动区间及时间含义写在详细内容中。只有整体先后有依据时建立“事件后于事件”，不靠同日日期或保存顺序推断。

5. 不增加普通字段的数据库必填约束。可理解的摘要、类别定义、对象说明及必要证据范围属于记录时的语义要求，不等于每个字段一律非空。

## 节点定义

属性均为单值；除四个身份 KEY 外均可缺省。KEY 在对应实际模型作用域内要求存在和唯一，不表示跨实例全局唯一。空字符串、业务身份是否正确及内容是否真实仍需记录方检查。

### 实际事件

**定义**：一次确实已发生或已开始、具有可区分身份的系统活动或发生事项。

**边界**：包括真实部署尝试、检查、故障发生、接报、决定形成和复盘；不包括尚未执行的计划、持续系统本身或仅为记录保存生成的递归日志。

**上级概念**：无。

**参考本体归属**：借鉴 UFO-B 事件及 BFO 发生体区分；本模型的业务事件不是对所有 BFO process 公理的声明。

**身份判定**：由来源、对象、实际执行或发生的连续性确定，不能仅凭摘要、日期或结果匹配。同一次活动的进展、结束、中止、补录和事实纠正保持身份；新的真实尝试、重新检查和独立验证采用新身份。重复接收同一回执不产生新事件。

**示例**：对生产服务的一次失败部署 A、随后真实重试 B，以及检查 B 的验证 C。

**反例**：“计划下周部署”不是已经发生的部署；B 成功不能把 A 的结果改为成功。

#### 属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 事件标识 | 事件稳定业务身份 | STRING | KEY；一事一键，不以时间或标题充当身份判定 |
| 摘要 | 已发生事项的简要描述 | STRING | 语义上应能看懂发生了什么；Schema 可选，不以空值自动判定事件不存在 |
| 发生日期 | 实际发生的日期 | DATE | 仅按来源精度记录；区间不得压成误导性的单日 |
| 发生时间 | 有据的实际发生时点 | ZONED DATETIME | 日期、时区与精度须有依据；区间可留空，不能填保存时间代替 |
| 观察或接报时间 | 观察或收到报告的时刻 | ZONED DATETIME | 不替代被报告事项发生时间；接报事件的两个时刻可能相同，但需各有依据 |
| 结果 | 本事件自身的结果或当前已知进展 | STRING | 可表达进行中、中止、失败、通过、未知等；无数据库枚举，未知终局不可写成功 |
| 影响与核实范围 | 对象、环境、版本、检查范围和限制 | STRING | 影响结论理解时必须可从事件及明确关联取得；不泛化到未检查对象 |
| 详细内容 | 必要过程、依据、时间解释和未决事项 | STRING | 保留真实尝试和更正理由，不机械填长文 |

#### 其他约束

- 事件记录的事实、来源报告和推断须可区分。仅收到报告时，采用本版接报方案，不因引用报告而断言被报告故障真实。

- 可同时属于多个确实适用的类别；类别关系不代替活动内容。为方便存储而双重分类不能制造已核实事实。

- 活动已开始可有记录，不要求预先知道终局。只计划开展的检查不得产生验证关系。

- 纠正同一事件的错误信息应保留更正依据及可追溯历史；更正记录不是重新发生了源操作。

### 事件类别

**定义**：供实际事件归类的受控词表条目，说明一类活动的适用与排除条件。

**边界**：类别是知识实例，不是每次活动，也不是每个类别对应一个新的 Node Definition。类别名称本身不提供事实证明。

**上级概念**：无。

**参考本体归属**：借鉴 UFO 类型与实例的区别；分类条目不直接声称是 UFO Kind 或 BFO universal。

**身份判定**：在约定词表中按“事件类别标识”及分类含义确定。改显示名不自动改身份；含义实质改变时不得默默复用旧键覆盖历史分类。

**示例**：“部署”类别可被 A、B 两次活动复用。

**反例**：“2026 年 11 月 5 日第一次部署”是实际事件，不是类别。

#### 属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 事件类别标识 | 词表内的稳定身份 | STRING | KEY；保持 Prod 的完整字段名 |
| 名称 | 可读类别名称 | STRING | 可重名，不充当身份；不增加 Schema 必填 |
| 定义 | 类别适用、排除与分类依据 | STRING | 分类前需取得明确含义；Schema 可选，缺失且无法确定含义时不能猜分类 |

#### 其他约束

- 核心初始化只创建类别的 Definition，不自动创建词表实例或强制每种类别一条记录。

- Prod 现有 incident 定义含“已报告或已观察到”，verification 定义为“实际完成的检查”。本版若采用接报及进行中检查方案，须另行确认所需类别定义；不能复制旧词表后宣称已支持新语义。

- 可复用现有语义准确的类别；需新增或改动词表实例时，同样遵守获准范围，不借初始化自动改写已有分类。

### 持续对象

**定义**：能跨多个活动保持业务身份的系统、部署实例、项目、环境、组织或其他参与及受影响对象。

**边界**：与其一次操作、其名称、某次状态和在事件中的角色不同；软件环境不是物理地点。

**上级概念**：无。

**参考本体归属**：借鉴 UFO-A 的身份分析和 BFO 持续体区分；聚合业务类型不统一宣称为 BFO independent continuant 或 UFO Kind。

**身份判定**：在可确认的实例、组织或业务作用域内按稳定身份确定。单纯改名不换身份；同名但不同部署实例不得合并。是否重建为同一系统需业务依据，不能由标识字符串独自决定。

**示例**：同一生产服务先后参与 A、B、C 三次活动。

**反例**：A 的一次失败部署不是持续对象；服务名称相同不代表测试环境与生产环境同一对象。

#### 属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 对象标识 | 作用域内稳定业务身份 | STRING | KEY；不只按名称去重 |
| 名称 | 供人理解的对象名称 | STRING | 可重名、可变；未知正式名称可用有据说明，不编造 |
| 对象类别 | 系统、项目、环境等说明 | STRING | 可选描述，不承担身份、继承或授权判断 |

#### 其他约束

- 对象在某次事件中的角色写在“事件涉及对象”关系上，不当作永久属性。

- 对象需稳定复用时才独立建节点；无证据确认具体对象时，不为补齐关系创建猜测对象。

### 来源

**定义**：可独立追溯、边界固定的一份材料版本、回执、观察记录，或明确组成和范围的固定证据包。

**边界**：来源是记录依据，不是其所描述的事件、真实结论或无限追加的活动容器。可变 URL 不等于固定版本；同一来源可支持多个不同范围的引用。

**上级概念**：无。

**参考本体归属**：借鉴 BFO 的内容与承载者区分及 UFO 的对象身份分析；本模型混合可追溯材料形态，不宣称严格对应单一上层类型。

**身份判定**：按出处、内容或版本及固定证据范围区分。同一材料版本可复用；内容或证据包成员、范围实质改变形成新来源身份。修正同一来源的定位错误不必新建，但须保留依据。证据包可在标题和定位说明其组成，不另造递归包关系。

**示例**：部署 A 的固定回执；验收 C 固定版本报告；列明这些材料及范围的证据包 S。

**反例**：“某网站首页”不足以唯一定位一份不断变化的验收报告；活动持续追加的新材料不能无说明覆盖同一固定包。

#### 属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 来源标识 | 固定证据单元身份 | STRING | KEY；业务键须能够区分版本和范围 |
| 标题 | 来源的简要说明 | STRING | 可选，未知不编造；证据包应有可理解的范围说明 |
| 来源定位 | 材料或固定包的可追溯位置 | STRING | 可为链接或可复查定位文本；缺少 URL 不等于来源不存在 |
| 来源观察时间 | 该来源所指一次观察或取得的时间 | ZONED DATETIME | 不因重复引用刷新为最近读取；多时点材料分别表达或在包说明中列清 |
| 来源实例 | 外部 KG OS 来源实例 | STRING | 仅在适用且已确认时填写 |
| 来源分支 | 来源的分支上下文 | STRING | 不代替不可变 State，也不证明当前 Head |
| 来源对象引用 | 来源 State 内的真实对象 Ref | STRING | 来源定位须明确该 Ref 对应哪个真实 State；不是跨分支或跨实例图边端点 |
| 来源操作前快照 | 来源操作前实际确认的 State | STRING | 与来源实例和操作对应；不填 VLog 保存基线冒充 |
| 来源操作后快照 | 来源操作后实际确认的 State | STRING | 不由操作成功推导不存在的快照 |
| 来源核验快照 | 来源验证实际读取的 State | STRING | 多目标或多 State 不塞入一个误导性的单值；分来源或在定位中逐项列明 |

#### 其他约束

- 必要出处与支持范围必须能够追溯，但不为机械完整而填满所有可选字段。

- 单份证据包的操作前、操作后和核验快照只能各指向一个可准确解释的 State；不能把多次操作混成一组三快照。同一来源含多个 State 时，来源定位必须明确来源对象引用对应哪个真实 State，不能只给一个 Ref 让使用方猜测。

- 受保护信息及无权披露内容不得因“记录来源”而写入。

## 关系定义

以下均为同一目标 State 内的二元图关系。每类可按真实业务多对多使用；没有本稿之外的强制基数。业务去重、无环、真实性及条件性完整性不是这些 YAML 已编码的数据库约束。

### 事件归属类别

**定义**：一次活动符合指定分类条目的含义。

（实际事件：被分类的活动）—事件归属类别→（事件类别：适用分类）

**成立条件**：已读类别定义，活动事实满足其条件；不凭名称或待执行目标归类。

**方向与限制**：事件到类别；可多个类别，同一事实不重复制造相同语义的边。不是继承，也不自动推理。

**时间要求**：表达对该次活动的分类；认识改变时可有据纠正，不表示事件重新发生。

**示例**：B → 部署。

**反例**：只有计划部署，却据计划创建实际部署事件并分类。

#### 关系属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 成立依据 | 本次分类的可说明依据 | STRING | 可选；已有内容足够时不重复填证明文字 |

### 事件涉及对象

**定义**：对象实际参与活动或实际受到影响。

（实际事件：活动）—事件涉及对象→（持续对象：参与或受影响者）

**成立条件**：有对象身份及参与、作用或影响依据。

**方向与限制**：事件到对象；一事多对象、一对象多事件均可，不表示拥有或永久角色。

**时间要求**：角色限于本事件；事件外是否继续成立不能由此推出。

**示例**：B → 生产服务 O，角色为“部署目标”。

**反例**：文档顺带提到另一系统，不足以把该系统连接为参与者。

#### 关系属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 角色 | 对象在该活动中的作用或影响 | STRING | 可选；不写为对象永久属性 |

### 事件引用来源

**定义**：来源与本事件的记录内容有明确证据或报告联系。

（实际事件：被记录事项）—事件引用来源→（来源：相关证据单元）

**成立条件**：来源定位及实际支持、报告或反证范围可以说明。

**方向与限制**：事件到来源；可多对多，不证明来源独立、正确或覆盖整个事件。

**时间要求**：材料生成、取得与事件发生可能不同；不得互相替代时间。

**示例**：接报事件 R 引用原报告 S，用途为“报告内容，尚未核实”。

**反例**：只要来源提到相同服务，就当作本次部署成功证据。

#### 关系属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |

### 事件后于事件

**定义**：有证据确认一个活动整体发生在另一个活动之后。

（实际事件：较晚活动）—事件后于事件→（实际事件：较早活动）

**成立条件**：真实顺序证据支持；长活动需能确定较早活动已结束、较晚活动随后开始。边界时刻相等时，只有证据确认先完成后开始才建立。

**方向与限制**：较晚指向较早；不自连、不形成严格先后循环；不等于因果、重试、依赖或数据库自动传递推理。

**时间要求**：只知同日、保存顺序、交叠区间或分别观察时间不足以建立。无精确时钟但实际先后证据充分时可以建立。

**示例**：A 已失败结束后开始 B，因此 B → A；B 正文另说明真实重试关系。

**反例**：两个同一天运行且互相重叠的任务，按日志写入先后连边。

#### 关系属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 成立依据 | 实际顺序的证据 | STRING | 可选；依据须可从相关内容取得，无依据不建边 |

### 事件验证事件

**定义**：一次实际开展的检查针对另一次活动的结果或声称进行核验。

（实际事件：验证活动）—事件验证事件→（实际事件：被验证活动）

**成立条件**：检查已经实际进行，目标身份、版本与范围明确；完成前只记录已开展和已取得部分，不提前给终局。

**方向与限制**：验证指向被验证活动；可多对多，不自连。关系存在不等于通过、全面覆盖或验证者独立。可验证此前验证活动，但必须是真正发生的另一次检查。

**时间要求**：所验证的内容在实际检查时可观察；不自动附加严格“后于”，边运行边检查可能重叠。

**示例**：C → B，范围为“生产版本 X 的启动与健康接口”，C 自身结果为失败。

**反例**：计划明天验收；或把 B 的部署回执直接当成独立验证通过。

#### 关系属性

| 名称 | 含义 | 值的类型或范围 | 语义要求与限制 |
| --- | --- | --- | --- |
| 验证范围 | 对该目标的版本、检查范围及限制 | STRING | 可选字段；范围必须能从此边、验证事件或明确来源取得；多目标结论逐目标对应 |
