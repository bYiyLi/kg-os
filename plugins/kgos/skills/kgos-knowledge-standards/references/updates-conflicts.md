# 知识更新、纠错与证据冲突

先比较是否为同一主体、同一命题、同一适用范围、同一时间/版本，以及相同的认识状态。它们不同，新旧文字不一致可能完全合理；不要先把两条记录标成冲突，再强行选一个赢家。

## 按差异性质选择

| 情况 | 判定依据 | 当前实例处理 |
| --- | --- | --- |
| 同一事实的重复输入 | 含义、身份、范围和证据没有实质变化 | 复用或不写；不虚报新增 |
| 补充 | 新信息增加兼容的细节或依据，未否定旧义 | 更新相应属性/已有关系；保留未涉及内容和原有效依据 |
| 纠错 | 有足够依据表明旧记录在它声称的时间/范围就是错误 | 修正错误内容并保留可解释的纠错依据；不伪造曾发生过的业务转换 |
| 现实变化 | 旧事实曾经成立，新事实从另一个业务时点开始成立 | 按既有有效期/状态/版本表达更新；不把旧事实改成从未成立 |
| 不同范围或语境 | 两者分别适用不同环境、地区、主体或条件 | 分别保留并准确限定，不互相覆盖或判为矛盾 |
| 未决证据冲突 | 同范围同时间互斥，现有证据无法裁决 | 不随意取最新、最多或某类来源；保留有归属的争议表达或报告不能忠实保存 |

保留纠错或变更依据，不授权追加本任务未允许改变的字段。已有模型及授权允许记录依据时才使用相应位置；没有这种位置时，在本次任务结果中说明依据与存储限制，不把 notes 偷偷改造成审计日志，也不自动写 VLog。

选择可以改变操作类别，但不能改变用户授权。例如有依据的纠错仍需处于已授权修改任务内；只读审查只提出修正。发现几项操作存在依赖时按 [写入与核实](write-verification.md)处理批次边界。

## 什么足以纠错，什么仍然未决

可用原始记录、可复现观测、明确的责任人确认或已指定的业务权威来源核对具体命题；“更可靠”要说明它为何适用于这个范围，而不是设一个通用来源等级。已证实是抄写错误时，不能因为旧值也在数据库里就保留为同等可信的结论。相反，用户只是要求保存第三方争议主张，并未提供裁决依据，就不能把它更新成已证实事实。

允许按用户/领域明确的采信政策选择操作值，但如存在未解决的反证，不把“按政策采用”报告成“已独立证明”。多个来源可能互相转载；一条后来发布的材料也可能只在叙述更早事件。记录到达时间不决定业务事实顺序。

## 时间、历史与归属

按模型区分发生、有效、观察、录入或更正时间。只有观察到新值，并不能推出其恰从观察时刻生效；没有证据不补旧事实的截止日。现有模型仅承诺“当前值”，且本次任务只需该值时，可据可靠证据更新，不要求为了本规范增建一套业务历史。

任务要求保留历史解释时，使用既有的业务版本/期间表达；若现有模型无法表达，明确缺口。KG OS 历史 State 可证明某时保存了什么，不能把旧错误因留在历史 Commit 中就称为业务上曾经成立，也不能用 Commit 时间替代有效时间。

**不要跨范围扩散变更。** 修正一个项目的状态、一个组织的任职、一份报告中的结论，只影响该事实实际适用的对象/期间。其它记录只有在明确依赖同一错误且授权覆盖时才同步修正；不能凭共享关键词全库替换。

## 撤回、失效与证据替换

来源撤回、链接失效或无法访问不自动证明原主张为假。它们改变证据的可用性或可信依据；核对是否还有其它证据、撤回原因是否真的涉及该命题。按既有模型标明变化，不能删除原材料后留下仍然显示“已证实”的无依据结论。

来源替换只在新来源确实支持同一命题/范围时成立；不同结论或不同版本的来源不能被当作一个 URL 字段的无害更新。明确需要保留来源各自说法时，不把两个矛盾内容拼成无归属的正文；能按现有结构表达则保存，不能则说明未决和具体表达缺口，不擅自创建通用论断系统。

## 结束当前判断

有依据的内容可继续已授权保存；未决项说明缺少哪条身份/事实/范围证据、因此哪项变更未执行。不要把整个库判坏，也不要无限要求外部确认。补充输入后只重新评估受影响决定，已完成且无需改变的独立结果继续保留。
