# 知识写入质量、核实与恢复

本文件只规定当前实例变更的正确性条件，不是一套 SDK 手册、事务引擎或 Branch 管理策略。操作签名、Patch 语法、错误和返回以当前 `kgos_docs` 为准。这里只记录影响知识正确性的必要区别。

## 写前边界

确定本次获准的知识库、写入分支、目标对象、拟改变的内容以及相关模型含义；已经明确的目标不反复询问，不凭默认分支替代用户指定分支。需要关联核对的模型和实例在同一 immutable State 读取，避免把不同快照拼成不存在的一组事实。读取失败不等于对象不存在。

用目标对象的实际 canonical 内容构造最小变更，保留无关字段与关系；输入未提供的可选值不意味着清空旧值。明确的清空/删除也必须服从已知模型和授权，不靠填空字符串或零值绕过必填约束。模型不匹配、必需证据缺失、对象身份冲突时只暂停依赖部分，不猜值、不放宽 Schema、不擅自改 Label 以逃避约束。

创建实例时，系统分配的 Object Ref 与调用方的业务标识分别处理；不要伪造 `n:`/`r:`，不要把请求临时 alias 当持久 ID。调用返回的实际映射是定位依据，不根据返回顺序假定与输入一一对应。相同业务键的创建冲突应触发身份核对，不能自动换一个键避开去重。

## 批次、并发与原子性

同一逻辑事实所依赖的对象和关系不可拆成“先写一半、剩下失败也算完成”。需原子完成时使用现行合同支持的一个原子操作；确有资源限制需分批，先说明哪些子结果能独立成立以及哪些仍未完成，不承诺不存在的全批次事务。独立记录允许分别完成，但不能忽略用户明确的全有或全无要求。

Object Patch 基于目标 Branch 真实 Head 的 immutable `baseState`；过期时重新读取并比较本次意图与他人变化，再形成新的最小 Patch。不要只换 baseState 字符串而复用旧目标内容，否则可能覆盖新值。Graph execute 的公共请求没有 Object Patch 的 `baseState`，不能加一个未支持参数来声称得到相同保护；读后写的依赖需要选择实际支持相应一致性保证的方式。

多次工具调用、一个 JavaScript 脚本、包含多个提交的操作不自动成为一个事务。失败发生在不同边界时，已完成的独立写入可能仍然存在；不得把最后异常泛化为全部回滚，也不能为恢复一条记录默认 reset 整个分支。

## 结果未知不是结果失败

| 观察到的事实 | 下一项允许判断 |
| --- | --- |
| 有确定成功回执和真实 State | 核实该 State 的目标内容及实际 Ref；不要以随后读回失败推断原写入回滚 |
| 服务端明确拒绝该原子 Patch | 按错误检查并修正原因；不声称同一脚本的更早独立写入也回滚 |
| 超时、取消、断线或成功回执丢失 | 先按原知识库/目标分支读取实际内容与必要历史，不盲目重建或重发 |
| 新 Head 已有与本次意图一致且身份可确认的结果 | 不重复创建；报告观察到的现态，不能无依据认定是本次调用产生 |
| 确认未执行，且现态仍满足原意图和授权 | 基于新读取的状态继续安全的未完成部分，不重做已完成副作用 |
| 无法核实执行结果或身份 | 报告该部分未知并暂停可能重复的写入，不用新随机身份“试一次” |

知识的业务键、来源事件标识或既有去重机制可帮助核对，但不自动构成全局 exactly-once 保证。没有这种模型能力时不能临时新增字段/唯一约束来补齐。关系替换可能有新 Ref，应按真实 transition 或重新定位的结果回读，而非继续操作旧 Ref。

## 分层核实而非只看成功码

**内容**：值及认识状态与实际依据相符，单位/时间/否定/范围没有变，未提供信息未被编造或错误清空。

**身份和关系**：对象属于正确知识库和范围；关系连到正确端点，类型/方向/角色/期间正确；没有产生同一事实的非预期重复。检查与本次任务相关的对象，不扩大成无界全库扫描。

**持久结果**：在实际结果 State 回读必要对象/关系，核对创建映射、更新内容、原子边界和应保留的不变量。检查跨快照最新状态只能证明新的观察，不冒充原提交的精确回读。数据库字段/约束通过不证明来源真实或主张成立。

技术输出缺失时保留“已写入但未回读确认”等准确状态；未执行只能给预期方案。若只完成一批中的部分，按事实说明哪些已完成、哪些拒绝/未知，不把全部合并成一个“成功”。报告服从用户任务形式，无需附加通用健康分数或强制 VLog。
