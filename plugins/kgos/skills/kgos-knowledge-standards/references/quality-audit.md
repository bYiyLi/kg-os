# 知识质量审计与使用验收

<!-- cspell:words SHACL Diátaxis -->

本参考补充条件化取证、审计覆盖、报告与合成对照。通用内容判据、精简标准及内容 Review 结果只在[主文第 3 节](../SKILL.md#knowledge-content-rules)维护；独立打开本参考时先读取该节及主文第 1 节的任务/授权边界，已加载且未变化时可复用。

按主文第 4 节的条件路由加载：证明强度看第 2 节；表达或过程归属的歧义看第 4 节的相关对照；独立审计或深入核验按实际范围使用第 1、2、3、5 节；方法依据仅在需要核对时看第 6 节。普通编写与内容 Review 不触发全量盘点、覆盖统计或审计报告，也不因读取参考获得执行测试、改库或扩展范围的授权。实际接口与执行/回读规则仍由主文第 5 节负责。

## 1. 确定范围和证据边界

在主文确定的目标与固定 State 下，明确本次审计的对象集合、问题和约定深度：

1. 按请求圈定单条、Definition/业务实体范围或整个知识世界，并核对相关 Ontology、关系与索引。跨 State 比较分别说明版本、业务时间和覆盖，不合并计数。
2. 全量审计先确定业务节点和关系的分母，排除系统内部元数据，并完成必要的分页与关系检查；查询受限时报告所检查的数量、查询条件和遗漏范围。抽样只对样本下结论；无法遍历全集时不得称“全库无问题”。
3. 将重要主张对应到实际可访问来源的版本、正文位置及所检查内容；只见到标题、Source 节点或 Commit 定位时，按第 2 节记录为定位证据，不算已核对原文。
4. 报告仅展示目标读者获准接收的结论、证据定位与必要摘述；可访问材料不等于可以公开全部原文，避免泄露凭证、个人信息、私有路径和未获披露许可的内容。

## 2. 按用途取证，不机械填字段

在主文内容判据下，针对有疑问的具体主张选择所需证据，区分以下证明范围：

- **来源可定位**：只确认资料存在或定位有效；尚不能说其内容支持某主张。
- **来源实际支持**：检查了适用版本和具体正文，确认它陈述或足以支持该主张；这是“来源说了什么”，不必然是“现实已独立证实”。
- **独立验证结果**：主张涉及实际部署、执行效果、测试通过或现行状态时，核对独立观察、测试记录及其环境、版本、范围。正式决策的权威记录可直接证明“决定已作出”，不强求运行证据证明决策存在。读取验证记录与执行新的验证是不同动作，后者依实际任务授权。

遇到来源相互矛盾，先核对业务身份、各来源的权威范围、适用版本和时间，再判断是合理差异、尚待裁决还是已证实错误，不按来源数量、发布日期或文字相似度定输赢。将核实所得用于主文的内容 Review 结果；来源不可读或版本不明时，受限的是依赖该来源的具体结论。

## 3. 审计步骤与问题验收

- **确定验收问题**：从知识的现实用途选择能区分成功/失败的问题，例如“某决策为何成立、适用于哪个项目、依据哪个固定版本”“某故障采取了哪项措施且经何种独立验证”。无关问题不成为必过门槛；仅做结果 Review 时不执行案例或使用测试。
- **执行取证**：读取对应 Knowledge 与必要关系，定向核对受影响身份、重复候选、时间/适用范围和来源；需要全量枚举时完成分组计数与必要分页。引擎一致性只证明存储/约束，不证明业务真实性。
- **核对用途**：检查现有证据是否找对对象、支持关键主张和关系推论，以及是否保留版本和限制。获准且需要真实使用验证时才运行代表性问题；否则报告静态判断及未验证部分。定位内容缺漏、证据不足、关系错误、检索/索引覆盖或未知，不一律提出改模型。
- **形成发现**：按审计证据分类为「已证实问题」「待核实风险」「合理差异」「未检查/证据不足」，并关联主文内容 Review 所判断的具体部分。缺少决定性来源时不把待核实升级为事实错误；确认矛盾也不自动表明哪一方为真。
- **提出改进**：在具体位置、缺陷、依据与修正之外，说明目标对象/关系、用途影响及可核实的验收问题。后续是否修改、如何处理模型缺口及回读，回到主文第 1、3、5 节，不因审计发现而新增权限。

### 审计覆盖、深度和成本

- **结构覆盖**：枚举了哪些业务节点、关系、来源和版本，实际分母与未读分页是什么；内部元数据不计入业务数量。
- **语义深度**：哪些主张核对了原始资料，哪些只核对了来源定位、字段/关系或抽样，哪些没核实。完成结构全量盘点不代表所有主张通过真实性审计。
- **使用验收**：哪些代表性问题实际运行、是否获得有证据且范围正确的答案；没有执行的验证保持未验证。

按任务和风险由结构扫描定位候选，对会指导行动、可能造成错误决定或影响多人/多系统的主张优先深查；已经充分确认且输入未变的部分可复用。发现已证实的高影响错误优先于纯格式空缺，但不以影响程度替代真实性判断。用户明确要求逐条完整核对时须完成约定深度，不能悄悄改为抽样；资源、权限或时间受限则交付实际覆盖和剩余范围。不要为凑固定覆盖率或分数反复读取无关资料。

## 4. 容易误判的场景

以下仅为合成文字对照，说明主文判据如何用于不同对象与用途，不是待执行任务或生产材料。同一个动作在对象自身的流程与本条的入库历史中，承担的作用可能不同：

| 对象、用途与问题表达                                                                                            | 按主文判据处理                                                                                    | 判断边界                                                                       |
| --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| 去重方法的 `limitations` 写“本轮已给本条改名，用户批准保存，旧条目保留”，这些经过与方法适用性无关               | 移出无关入库经过；方法保留影响去重判断的身份、条件和限制，留痕需求交由已有且获准的维护记录        | 被移出的是与对象/用途无关的经过，不是因为出现改名、批准或保留等词              |
| 有据的知识迁移方法写“确认身份/键对应，取得迁移批准，提交后回读；按保留策略处理旧节点”，审查者拟因“维护过程”删除 | 保留支撑迁移执行和核验的步骤、授权条件及有据的失败/恢复边界；迁移或审批方法本身就是此条描述的对象 | 方法内容不授予读者执行权限，也不把本条实际获准保存混成迁移已经获准             |
| 一次维护事件记录实际审批、改名和核验经过                                                                        | 按事件用途保留能说明发生了什么及其依据的过程                                                      | 仍须区分计划、尝试和结果；事件归属按真实模型与 Skill 职责处理，不自动写 VLog   |
| 来源明确标注“方案草案 0.1”，或正式文档标注“版本 2”；另一条事实仅尚未核验                                        | 前两者忠实表达所述文档的真实状态/版本；后一条只标明具体主张的证据边界                             | 草案和版本不是禁词；不把未验证改写成对象未完成，也不为知识入库默认生成草案版本 |
| 经验写“先调整就恢复了，说明调整解决了问题，以后都这样”                                                          | 保留原材料的结果观察及归属；原因解释按实际支持表达，可迁移结论收窄到有据前提                      | 不从先后推出因果，不编造反馈/对照，观察部分可独立合格                          |
| “甲批准、乙交付、丙验收”只引一份批准通知                                                                        | 分清主张及各自来源，对尚无依据的交付/验收明确未知或来源归属                                       | 批准通知不单独证明另两项动作完成，不强制每句建节点                             |
| Claim 用于判断导出是否保留关系，却只写真实的“工具 X 支持导出”                                                   | 明确当前只确认导出功能，关系保留能力未注明；有来源后再补所需能力和限制                            | 事实可真实但不足以支撑该用途，不猜测缺失能力                                   |
| Procedure/建议三栏齐全，却只写“打开工具，注意准确、提高质量”                                                    | 有据时给出可用判断，例如同名异键代表不同对象时保留，身份待核不合并，对确认重复提出合并建议        | 该例不授权合并，事实条目也不必写步骤                                           |
| Case 只记工具 X 在离线样本的一次成功，简写为“该方法可靠”                                                        | 保留材料实际记载的环境、样本范围和一次观察，不扩大成普遍可靠                                      | 不补造未记载版本；精简不能删掉决定适用范围的条件                               |
| Decision 缺日期，原文也未注明；或正文有日期而相应字段为空                                                       | 前者说明未知及用途限制；后者核对日期的身份与语义后，报告有据表达缺漏                              | 不把所有空值统一判错或自行补日期                                               |
| 同名记录身份键/来源或有效期不同；两份报告结论相反但适用条件不同                                                 | 分别核对身份和条件，确认是同一对象/条件下的重复或互斥主张后才进一步裁决                           | 名称相同不自动合并，不同观点不自动判事实冲突                                   |
| 已有 Source 关系却不支持所连主张；或材料只证实构建，正文写已部署验收                                            | 定位不支持的主张/关系，按第 2 节核对实际证明强度                                                  | 引用存在、数据库一致性有效和自述成功，均不替代对应事实的证据                   |
| 全库请求只读到第一页/Top-K，或重要决策虽可搜到却无法追溯依据                                                    | 前者披露未覆盖部分；后者指出具体证据/关系缺口及其用途影响                                         | 检索存在不等于用途已验收，局部命中不证明全库无缺陷                             |

## 5. 报告质量与停止边界

按任务输出目标 Instance/Branch/State、结构覆盖、实际语义核验深度、真实使用问题及结果、重要发现与可披露依据、未检查的限制、建议动作。有数量时标注真实分母和计数单位；只对确认的对象下结论，不套用固定分数或伪精确百分比。按用途影响优先呈现重要问题，证据披露遵守第 1 节边界。发现为零可以是完整结果，不为了制造整改任务重复检查或扩大范围。

- [W3C Data Quality Vocabulary (DQV)](https://www.w3.org/TR/vocab-dqv/)：借鉴按使用目的选择维度、将维度与具体评估方法分离；不引入 DQV/RDF 本体或固定权重。
- [W3C PROV-O](https://www.w3.org/TR/prov-o/)：借鉴事实来源、活动和责任归属及版本衍生的区别；不强制创建 Entity/Activity/Agent 节点。
- [W3C SHACL](https://www.w3.org/TR/shacl/)：借鉴目标范围、约束和逐项验证报告；KG OS 使用当前 Property Graph/Constraint，不声称原生支持 SHACL。
- [FAIR Guiding Principles](https://www.nature.com/articles/sdata201618)：借鉴可发现、可获取、可互操作、可复用，特别是稳定身份与来源；不机械加入科研数据许可字段。
- [Quality assessment for Linked Data: A Survey](https://journals.sagepub.com/doi/10.3233/SW-150175)：质量与用途相关，涵盖真实性、一致性、完整性、时效及可理解性；不用通用分数代表知识可信。
- [Great Expectations validation](https://docs.greatexpectations.io/docs/core/run_validations/)：借鉴期望条件、实际验证结果和失败对象清单；不引入额外运行时框架。
- [Wiki Audit Skill](https://github.com/kfchou/wiki-skills/blob/main/skills/wiki-audit/SKILL.md)：借鉴按主张核对引用是否真实支持、标出无证据主张；不把其 Wiki/脚注或并发子 Agent 流程直接移植到图谱。
- [Knowledge Base Optimizer Skill](https://github.com/craviart/knowledge-base-optimizer/blob/main/SKILL.md)：借鉴盘点结构、来源真源和非破坏性纠错；不引入其文件备份、路径搬迁与知识库重组工作流。
