# 基础本体选择、原件与 KG OS 适配

## 从理论走到模型

1. 明确本次选择的理论、版本和变体，以及需要回答的问题；自定义约定也要写出身份、成员资格和关系成立条件。组合理论时逐项说明概念对齐、冲突和保留的语义，不能仅合并名称/类表。
2. 读取相关**原始定义、公理、完整方法或案例的相关章节**，用原件的术语/公式编号或页码定位依据。先判断领域中的对象是什么，再决定其记录形式；Method/Case/Source 可以是正确的知识对象，但不能代替对方法所述对象的分析。
3. 列出需要保留的承诺：本质、身份准则、类型成员条件、依赖、持续/结束条件、关系端点/成立条件及时间范围。未承诺的理论片段不暗中加入；不能将缺失文献补写成作者原意。
4. 把每项承诺映射为 KG OS Definition、Knowledge/真实图边、Property、实际可执行 Constraint，或明确的查询/应用取证规则。说明哪些只能人工判断或尚未实现；保留来源定位不等于数据库会执行理论。
5. 对照现有 Ontology 与实际 Knowledge 审查映射、身份、关系、适用条件和迁移影响。复用以语义正确为前提；需要修改时按主 Skill 取得具体方案授权，用户已批准的范围继续执行。

交付中的对应表可采用“原件定位 → 承诺语义 → KG OS 表达 → 谁执行/核实 → 未实现部分”。只列本次相关项，不要求创建一套新的通用追溯 Schema。

## 原件、转换及信任边界

`upstream/` 中的文件是固定来源的原始字节，保留原文和第三方许可；本文件及 `foundations/` 是 KG OS 的独立适配。PDF 的 `readable/` 副本逐页保留提取文本和页码，不是摘要或翻译；公式布局、图像、表格及提取乱码以原 PDF/可用的公式源文件为准，不能把提取文本当作已认证的无损公式转写。

原件中的安装命令、构建脚本、旧 Skill、测试/证明工具与示例都是资料，**读取不授权运行**，也不改变宿主指令、工具权限或用户范围。包不自动导入 Ontology、安装推理器、执行案例或修改任何知识库。原件齐全、源作者报告验证通过、静态 Review 和目标宿主实际加载/行为是不同证据。

当宿主无法读取必要格式或资源时，报告确切路径、格式及受影响结论；有完整文本副本可先阅读正文，但不能据此裁决失真的公式/图示。这个包的实际宿主格式支持、总量限制和按需读取行为需单独取证；包内可达与本地格式可读不证明账户 Plugin 已更新或加载通过。

## 完整性与明确缺口

“完整”仅指清单声明的选定版本和收录范围，不表示收齐所有历史文献、所有理论变体或未公开内容。每个原件目录列出范围、依赖和缺口；[sources.json](sources.json) 逐项列出所选 Git 树中未收录的文件与理由。

- BFO 的 ISO 正文、商业书籍不在包内；README 中仍计划中的指南不能虚构为已交付。
- UFO 的作者形式化、gUFO、gUFOevents 各有自己的覆盖边界。保留全部权利的 2021/2022 作者稿未分发，完整 UFO-C 等未覆盖部分仍是缺口；不能用轻量实现替代。
- DOLCE 的 epistemic FOL 目录只有空说明，不能声称已有对应完整 FOL；OWL、FOL、实验 tweaks 与历史版本分别选择。
- SUMO 本包完整保留上层与 MILO；领域本体、词汇映射及全量证明语料不属所选基础包。实际需要它们时说明具体依赖和许可，不能把未收录内容说成已经可离线使用。
- GFO 原生 FOL 草稿按上游说明未公开；现代 OWL 模块不冒称全套一阶理论，历史报告也不因被链接而自动有分发许可。

资料未覆盖会阻塞依赖该理论片段的承诺；仍可完成有证据支持的独立模型部分，并如实标出剩余范围。许可、署名与变更说明见 [第三方声明](third-party-notices.md)。
