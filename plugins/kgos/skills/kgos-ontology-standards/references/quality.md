# 本体质量标准

适用于创建方案、现有 Ontology 评审以及模型变更的质量判断。标准版本继承 `SKILL.md` 的 `metadata.version`；下列 Q1–Q8 是本规范的审查定位符，不是数据库字段或必须写入知识库的标签。只检查与当前范围有关的维度，避免把一次字段修改扩大成全库审计。

## 八项质量标准

| 维度 | 应作出的判断 | 需要的依据 | 常见误判与边界 |
| --- | --- | --- | --- |
| **Q1 需求充分性** | 每个明确要求支持的问题有可解释的字段/关系路径；遗漏需求应补模型或明确不支持 | 用户目标、实际问题、示例实例及查询路径 | 不以字段多代表完整；不强迫未知未来需求进入当前模型 |
| **Q2 语义清晰性** | 概念和字段有一致含义、实例边界；相邻概念能区分；歧义不能靠同名约定猜测 | 定义正文、上下文、包括/排除实例 | `description` 在 Kernel 可选；缺描述不自动是非法 Schema。无法从其它依据消除歧义时才是质量缺口 |
| **Q3 身份与粒度** | 区分同一对象、不同版本、重复采集、同名不同对象；键的唯一范围符合业务 | 身份来源、生命周期、相同/不同实例对照 | 元素 ID 不是业务身份规则；标题/姓名不天然唯一；无需给所有类型统一添加业务 id |
| **Q4 结构与约束一致性** | 类型、端点、存在性和唯一规则相容；声明符合实际 KG OS profile；业务规则的执行层明确 | 当前公共模型、结构解析/回读、有效与无效实例 | 描述中的枚举、顺序、不重叠、数量限制不等于数据库已强制；约束通过不证明业务事实真实 |
| **Q5 最小充分性** | 每个新类型、字段、关系或约束解决当前可指出的问题；复用不会损害原义 | 需求到结构的对应、已有模型比较、简化候选 | 不为“图谱化”拆每个值；也不能把必需的关联/来源/时间全部埋入自由文本来减少类型 |
| **Q6 可查询与可理解** | 目标问题能定位到实际对象和关系，时间/来源过滤不会改变问题含义；索引有访问需求依据 | 代表性查询及结果、索引目标、数据规模/访问事实 | 没有索引不直接代表不可用；有全文/向量索引不证明召回或答案质量；查询成功不证明语义正确 |
| **Q7 可演进性** | 区分扩展、改名、重定义和迁移；新需求不被伪装成旧概念的同义替换 | before/after 意义、已有实例、调用方依赖、迁移规则 | 不为可扩展提前建层层抽象；保留历史 Commit 不意味着当前应用仍兼容旧字段 |
| **Q8 可维护与可核实** | 能指出变更影响、验证方式和未知范围；维护不毁掉已有语义与依据 | 相关 State、准确对象范围、实际变更/回读、例外记录 | 不以最近没实例就删除类型；不以恢复分支抵消外部副作用；不把计划当已执行 |

## 建立可解释的定义

新建或重定义一个概念时，应能回答：它表示什么、一个实例的粒度是什么、如何区分两个实例、哪些邻近概念不属于它、关键属性/关系的业务含义是什么。信息可以由明确的用户材料和已有模型提供，不必复制成五个固定字段。

例如“发布版本”若表示一次可独立引用的软件发行，与“组件当前版本字符串”不同。前者允许多个版本并存，后者是组件的一个状态值；不能仅把字段名从 `currentVersion` 改为 `release` 就声称完成模型升级。

字段含义不明显时，说明值域、单位或时间角色以及缺失语义。`date`、`status`、`type`、`value` 本身不足以证明这些含义已定义。采用更明确名字或描述均可，不强制统一命名语言或禁止所有通用名字。

## 验证优秀而非验证整齐

为当前需求选择能区分设计选择的实例，不要求固定数量。至少覆盖实际存在的歧义边界，例如同名不同实体、同一来源两次采集、未知截止日期、相同版本号属于不同组件。有写入授权也不能为了教学把案例数据写进用户业务库。

从实例回答需求问题，检查：答案所用的对象是不是问题所指对象；时间区间与知识版本是否区分；关系方向和角色是否准确；缺失值有没有被错误解释；结果是否依赖未说明的约束。概念设计可用纸面实例推演，实际数据库正确性需要独立执行证据，不能混为一种验收。

## 审核结论及强度

**已确认问题**：存在明确需求/合同和可重现反例，当前模型无法正确表达或执行。例如要求区分两个来源版本，模型却只以 URL 唯一；有重复遗留值却直接收紧唯一约束。说明对象、依据、影响和最小改法。

**改进建议**：当前仍能满足需求，但存在可解释的理解或维护成本。例如相同含义用词不一致。给建议和理由，不当作强制迁移或阻止其它合法任务。

**未知/待领域判断**：实例范围、来源、历史或实际查询不可得。写明缺什么、影响哪条判断；不凭名称相似、样本少或模型体量打分。

**不适用**：当前任务不涉及该维度，例如静态术语未要求有效期。不要补造时间、出处或状态字段以凑齐检查项。

审查必须保留“未发现已证实问题”和“已证明所有情况正确”的区别。Doctor 消费本规范时沿用这个证据边界；不把一个局部案例的业务政策提升为所有 Knowledge Base 的标准。
