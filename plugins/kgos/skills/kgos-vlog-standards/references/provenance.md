# 时间与跨知识世界追溯

追溯要求是能准确定位依据及解释范围，不是强制字段模板。使用已有模型及真实来源可提供的定位；没有独立外部文档时可以表达用户陈述或实际回执，不能伪造URL、Run ID或Commit。

## 区分来源与记录容器

对KG OS中的活动，应能辨认实际源库/Instance、操作时Branch语境及相关固定State；针对对象/差异的结论还需对应Ref或变化范围。只知道Commit而无Branch起源时可记录已知版本，不能凭祖先猜唯一来源Branch。只知Branch且历史State无法核实时，就限定为当时观察/报告，不能用当前Head伪装当时版本。

修改前、修改后、验证所读State可能不同，按各自角色保存；一次任务多个Commit不强制拆成多个独立事件，也不能用最终Commit冒充每次操作/验证版本。来源是外部部署、文件或测试时使用其实际身份与证据位置，不要求必须有KG OS Commit，更不能把它放进KG OS StateRef接口。

VLog写入以目标记录Branch自己的Head为基线；来源State只作为被记录事实的上下文。源活动完成、VLog写入和回读是不同操作，不宣称跨Branch或跨Instance原子提交。VLog的返回State表示何时保存了记录，不替代源操作结果State或业务发生时间。

当前记录自身的最终Commit只有写入返回后才知，不预填或猜测。无需把“包含自己的最终Commit”变成记录必填项，也不能每次补写又产生新Commit再继续循环；需要向调用方提供记录定位时用返回的State+Ref，既有外部登记需求另按实际合同处理。

## 来源定位值不是跨快照边

`n:`/`r:`需与实际库和所读State一起解释。把另一Branch的Ref放在普通Property或来源说明里，只是定位数据，不会创建跨Branch关系或导入端点。建立真实图边要求端点在目标Snapshot中按对应语义存在；不能为方便连接而合并源世界、复制整套模型或指向恰好同号的本地对象。

同一来源对象后来修改、重命名或删除，历史引用仍要按原State解释，不自动改指最新同名对象；相同字符串在不同Instance也不保证同一身份。实际源库无法访问时保留已知定位与来源归属，明确未复验，不假装已读；当前连接地址变化不等于来源实体身份变化。

## 最小充分证据与可用性

关键结论需要可解释的结果摘要及实际证据位置，不能只有一个今后可能过期的临时链接；有条件且获准时保存足以理解结果的必要摘录。URI、内容摘要和签名字符串本身不保证材料真实或永久可访问；不要宣称已归档未保存的正文。

读取源库的权限不自动允许把原始私密资料复制进访问范围不同的VLog。定位也可能泄露私有路径、人员或凭证参数，使用已批准的最小定位/脱敏表达，见 [记录演进与披露](evolution-safety.md)。权限不足保留来源受限，不通过记录复制来绕过访问控制。

固定State的内容与附加State Data不同：后者可变，不因引用Commit就变成当时冻结的证据。实际引用sidecar、移动Tag、网页或任务页面时保留所读时点及可变性；需要长期证据的保留措施按现有任务授权，记录本身不自动建立备份、Tag或保留策略。
