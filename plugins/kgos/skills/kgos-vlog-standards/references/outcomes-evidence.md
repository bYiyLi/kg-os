# 执行结果与证据

结果的可信度取决于实际观察，不由描述中的“完成”或status值自动产生。本文件约束如何写，不能用记录任务的授权替代实施、验证或修复授权。

## 分层描述已知事实

| 实际证据 | 可以记录什么 | 不可据此推断 |
| --- | --- | --- |
| 方案、批准或任务已登记 | 计划/决定及实际依据 | 已开始执行或已完成 |
| 收到调用接受/进程启动回执 | 请求已接受或已启动，说明真实对象 | 持久变更成功、效果通过 |
| 操作成功返回 | 该操作在回执合同内完成 | 所有外部效果均验证、全任务成功 |
| 持久内容回读成功 | 对应版本的实际保存状态 | 内容所描述的现实事件因此为真 |
| 对应对象/环境/版本的验证完成 | 在该检查范围内的结果 | 未测环境、未覆盖项或后续版本也通过 |
| 超时、取消、丢回执 | 哪一步被观察到、其余结果未知 | 操作必定没执行、失败或回滚 |
| 明确拒绝或验证失败 | 具体失败及已知影响，保留其它已完成部分 | 整个多次调用流程自动回滚 |

不要把“修复已应用、验证失败”压成success，也不要把已知操作成功因记录失败改成业务失败。部分成功按目标/步骤区分；重试后的成功不使此前失败从未发生。缺证据可以记录明确限定的未知/待核实事实，模型能表达时不必等所有调查完成再保存。

## 结论须对应可复核的范围

保留支持关键结论所需的目标、相关版本/环境、实际执行和验证依据。命令计划不是执行日志，代码修改不是部署，部署回执不是测试，退出码零不独立证明期望测试被收集且没有跳过。适用哪些检查以源任务为准，不由VLog增加统一测试门禁。

“原因已确认”需要支持该因果的证据；采用某补救后恢复只能先支持该观察，不自动证明唯一根因。观察、操作者报告、AI推断和独立复验分别归属。用户明确说明亲历结果可记录为其报告，没有工具痕迹不一律拒绝，但不能写成AI亲自验证。

一次巡检的记录要保留真实覆盖和遗漏：抽查20条未发现问题不能写全库健康；任务执行结束但检查因权限失败，也不是零问题。根据已有来源能确定日期/时区/精度就保留；未知开始/结束时间不填保存时间，跨系统时钟不一致时不猜先后顺序。

## 周期任务证据而非调度控制

定义、启用、触发、启动、运行完成和结果验证不同。记录某次Run的事实以及已知覆盖/时间；没有记录不证明没运行，有记录也不证明调度当前仍启用。只看到外部任务计划时不补造成功Run，不为使Doctor通过写预期结果。

“最近运行”按真实运行时间及已定义维护要求解释，不按VLog最近编辑时间刷新。旧事件的文字更正可能产生最新记录Commit，却不意味着今天执行过维护。没有可靠运行时间或适用频率依据时说明无法判断，不自设过期阈值。

Doctor可读这些记录作为证据，但“已记录通过”不能自证真实成功或客户端可用；模型可识别性、证据是否充分、当前调度状态各自核对。本规范不启动任务、安排下一次检查或修复记录所述问题。
