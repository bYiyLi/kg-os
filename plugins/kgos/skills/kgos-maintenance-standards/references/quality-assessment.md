# 质量候选与问题确认

维护须区分**候选异常、证据支持的真实问题、合理差异/无需处理**。三者是宿主当次判断，不是固定Node标签、Issue状态字段或数据库自动质量分数。

## 重复不等于同一对象

名称相同、语义文本相似、属性大部相同、全文/向量分数高，都只说明值得核对。按真实模型的实体粒度、稳定业务键、身份作用域、有效时间和关系角色判断是否同一身份；业务键可能仅在某项目/来源中唯一。同名不同人、同人不同事件、多次独立观察、同内容不同来源均可能合理并存。

“对象重复”与“知识事实重复”不同：两个节点可以确认为同一业务对象，但其各自关联不同来源、时间的事实仍需保留；同一来源对同一事实的重发与两个独立来源的相似证据也不能同一方式删除。关系的判等依类型、正确端点、方向、角色、期间与模型要求；同类型同端点不意味着只允许一条关系。

某候选因为查询缺少稳定键或部分关系未读而尚不确定，就不能任选一个“主节点”，也不能通过更高相似度制造确定身份。模型已经确认同一作用域稳定键唯一且找到两个同键对象时，可以认定存在身份约束/数据整理问题；如何保留实例、边、证据是另一个处置决定。

## 矛盾只在同一可比语义下成立

先核对同一主体/身份、属性或主张含义、适用对象、时间区间、条件、来源归属和认识状态。两项建议分别适用不同目标，不是矛盾；两项来自不同作者的相反**主张**可以都是真实存在的意见，不必二选一；过去正确的历史记录也不因今天事实改变而成为错误。

同一人同一有效期在已确定互斥的约束下出现两个无法兼容的确定值，才构成应处理的候选冲突。确认冲突不自动确认哪项真实，除非已有依据能够裁决。记录的陈述、当前世界实际事实和AI推断之间不要互相升级；更晚的提交时间不代表更可靠的业务事实。

## 过时、缺失与模型不适配

“三年没更新”不证明内容失效。若知识有明确时间有效性、依赖于已经改变的外部条件、或用户要求核实当前适用性，则针对该条件验证；没有证据证明失效时，标注未复核/未知优于删除历史。过时的信息仍可能作为历史证据有价值。

缺字段、缺边或孤立节点不是通用错误：先读对应Definition/业务约束及是否允许可选值；在开放世界里数据库未保存某关系不证明关系为假，不能捏造关系填洞。已确认模型要求的关系/属性确实缺失，或某项已成立的事实无法被正确表达时，指出具体质量缺口。模型本身不支持业务时间或来源差异，属于模型设计问题，不在此Skill发明字段或Definition。

数据库 Constraint/Schema 检查可以证明某些结构条件，却不能证明所有事实真实；Graph原样执行甚至可能写入与KG OS上层意图不相符的知识。一次历史有效、当前不再有效的关系，不宜用“旧记录是错的”代替业务时间判断。

## 三种结论与后续动作

| 证据结果 | 应如何处理 |
| --- | --- |
| **已确认质量问题** | 说明违反的具体模型/事实条件、对象及证据；进入合适处置判断，未经授权不写 |
| **尚待确认** | 保留明确候选、未知原因和足以改变结果的必要证据；可继续有界核实，不强行修复 |
| **合理差异/无需处理** | 说明区别成立的来源、条件或身份，不因“去重率”强制合并或删除 |

已给足够身份和范围依据时不要求永久延后；确实缺关键业务判定且无法从已授权资料裁决时，将具体未决选择交给宿主处理，而不是追加新的通用审批流程。缺一个索引不自动构成“需要重建索引”的维护结论，实际索引/Provider异常由对应运行时/模型owner处理。
