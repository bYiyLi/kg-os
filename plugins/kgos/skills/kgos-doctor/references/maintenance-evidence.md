# 持续维护与 VLog 证据

D5 分别报告**任务配置、实际执行、VLog 记录与验证、未决事项连续性**。维护可以手动进行，不要求为每个知识库建立 Scheduler；普通 `branch/vlog` 也不是内核保留空间。

## 外部任务与执行

只读当前宿主实际开放且已授权的任务接口，核对任务与目标知识库的对应关系、定义、启用状态、计划/时区、实际运行及结果。列表只有定义时，仅判断配置；不根据启用、下一次时间或列表存在推断运行成功。没有调度接口时为 `UNKNOWN`，不停止独立可做的 VLog 检查；MCP 失败也不阻止已授权的外部任务只读核对。

近期性依据任务真实周期、时区、首次执行时间及当前时间；没有这些依据，不发明统一过期天数。未来首次运行不算遗漏；按需手动维护没有固定到期时间。已确认无周期任务可给非阻断 `WARN` 与可选建议，不宣称知识库不可用；明确停用或到期未执行说明实际状态，真实失败记 `FAIL`。重试、取消、部分完成和结果未知分别说明，不能把“任务已触发”写成维护成功。

## 按实际模型读取 VLog

通过当前 `kgos_docs` 的 `guides/evolution.md`、`guides/reading.md` 及实际 SDK 页理解读取。确定 `branch/vlog` 是否存在并解析其 Head，按 D2 核对目标 State，再读取该 State 的实际 Ontology。缺失 Branch 提示 `WARN`；权限/连接/模型语义不可确定时，受影响结论 `UNKNOWN`。不创建分支，不把默认 Branch 的内容当 VLog，也不读取仓库 `docs/vlog/` 代替运行记录。

根据现有 Definition 描述、属性、关系及有限样本，辨认记录身份、任务/单次运行、发生时间、结果/验证、未决事项和来源定位。它们可以由一个节点、多节点及关系表达，也可以在有证据可解释的正文中表达；不要求 `VLogEntry`、固定字段或状态枚举。不明确的含义只标未知，不强制迁移到示例模型。

在已辨认的实际语义下有界定位近期相关记录；查询使用真实字段/关系，按实际发生时间而非写入/修改/Commit 时间判断运行。时间不可辨认或覆盖不足时不能宣称“最新一次”。继承的普通业务数据不自动算日志，同标题不证明同一任务/同一运行，旧失败后的纠错也不自动构成新的维护执行。

记录中的成功是所记录的主张。分别核对可得的运行回执、验证范围和关联来源；源 Instance/Branch/State 与保存记录的 State 不混用。只有日志自述时可以确认“存在成功记录”，不能升级为“源操作及效果独立验证通过”。缺来源证据不直接推断失败；来源不可访问时说明该限制，不跨越权限追取。定位字符串不产生跨快照图边。

## 记录质量与连续性

需要判断记录质量时，按宿主实际可取得的 `kgos-vlog-standards` 及其版本读取相关规则；维护连续性按可得的 `kgos-maintenance-standards`。没有规范不妨碍报告已观察的任务/记录，但规范符合性为 `UNKNOWN`，不复制或发明质量标准。

以可追溯身份关联旧问题、后续处理、再次运行和复核结果；报告已解决、仍未决、可能复发或无法确认的区别。未读到后续不能断言无人处理，问题存在时间长也不等于逾期；据实际约定和证据提示缺口，不创建 Issue、补写日志或执行修复。

外部任务与 VLog 不一致时保留各自结论：历史成功记录不证明调度仍启用，运行成功不证明记录已保存，记录已保存不证明验证成功。必要证据已充分或明确受限即交付，不为消除 `UNKNOWN` 建立任务、执行测试维护或强制新增记录。
